# 주간 진행 기록 — 역할극·학습 대화 에이전트 POC

> 작성일: 2026-09-09  
> 목적: 이번 주에 진행한 POC 구현·검증 작업과 현재 확인된 이슈 정리

## 1. 이번 주에 진행한 일

이번 주에는 전체 서비스를 완성하기보다, 대화 에이전트가 실제로 어느 정도의 처리 시간·토큰·비용을 사용하는지 측정하고, 각 단계의 병목을 확인하기 위한 POC를 작성했다.

이 서비스에서는 아동이 역할극 속 캐릭터와 대화한다. 평소에는 캐릭터가 자연스럽게 대화를 이어가고, 아동이 어려움을 겪거나 도움을 요청하면 마스코트가 힌트를 제공하는 방식이다.

이번 POC에서는 다음 내용을 코드와 실행 결과로 확인했다.

- 상황 분석, 응답 생성, 응답 검증 단계별 처리 시간
- 한 턴에서 발생하는 AI 호출 횟수와 단계별 병목
- 입력·출력 토큰과 확인 가능한 API 비용
- 각 단계가 순차적으로 실행될 때 발생하는 전체 응답 지연
- 위험하거나 개인정보가 포함된 입력·응답을 차단하는 흐름
- 기본적인 상태 전이와 에이전트 처리 결과 기록

현재 POC는 실제 서비스 전체가 아니라, 에이전트 구조의 성능과 비용을 측정하고 개선 방향을 찾기 위한 실험용 코드다.

## 2. 현재 POC의 동작 방식

현재는 아동이 한 번 입력할 때마다 여러 단계가 순서대로 실행된다.

```text
아동 입력
  → 입력 내용 확인
  → 현재 상황 분석
  → 캐릭터 또는 마스코트의 응답 작성
  → 응답 내용 재확인
  → 안전성 확인 후 전달
```

현재 구조에서는 응답을 보내기 전에 AI가 다음과 같은 일을 모두 처리한다.

1. 아동이 현재 상황에서 어떤 어려움을 겪고 있는지 분석한다.
2. 캐릭터가 할 말을 작성한다.
3. 작성된 말이 상황에 맞고 안전한지 다시 확인한다.

이 구조는 안전성을 확인하기 쉽다는 장점이 있지만, 모든 단계를 기다린 뒤 응답하기 때문에 시간이 오래 걸린다.

## 3. 이번에 확인한 내용

### 대화 흐름

- 일반적인 상황에서는 캐릭터가 응답한다.
- 같은 부분에서 여러 번 막히면 마스코트가 개입할 수 있다.
- 아동이 다시 진행하면 이전의 정체 상태를 초기화한다.
- 도움을 거절한 경우에는 매번 반복해서 개입하지 않는다.
- 대화 중 어떤 목표를 시도했는지와 도움을 받았는지를 기록한다.

### 안전성과 개인정보 보호

- 위험한 입력은 AI 응답을 만들기 전에 차단한다.
- 전화번호, 이메일, 주소와 같은 개인정보는 AI와 기록에 전달하기 전에 가린다.
- AI가 괜찮다고 판단한 응답이라도 금칙어나 개인정보가 있으면 전달하지 않는다.
- 안전성 확인에 문제가 생기면 안전한 고정 응답을 사용하거나, 그것도 안전하지 않으면 응답을 보내지 않는다.
- 중복 입력이나 순서가 맞지 않는 입력은 거절한다.

### 테스트와 기록

- 정상 대화, 도움 요청, 반복해서 막히는 상황, 회복 상황, 위험 입력 등을 테스트했다.
- 실제 AI를 호출하지 않는 가짜 테스트와 실제 API 연결 테스트를 나누어 관리했다.
- 각 단계에 얼마나 시간이 걸렸는지와 호출 횟수·비용을 결과 파일에 남기도록 했다.

## 4. 최근 실행 결과

최근 실제 API 연결 테스트에서는 한 가지 대화 사례를 5턴 진행했고, 총 18번의 AI·안전성 확인 호출이 발생했다.

| 항목 | 결과 |
|---|---:|
| 대화 턴 수 | 5턴 |
| AI·안전성 확인 호출 | 18회 |
| 일반적인 응답 준비 시간 | 약 14.8초 |
| 느린 응답 구간 | 약 18.3초 |
| 확인된 비용 | 약 $0.0095 |

이 결과는 아직 최종 품질을 평가한 것이 아니라, 현재 구조가 실제로 얼마나 걸리는지 확인한 결과다.

## 5. 현재 가장 큰 문제 — 응답이 늦다

현재는 아동이 메시지를 보낸 뒤 다음 과정을 모두 기다려야 한다.

```text
상황 분석 → 응답 작성 → 응답 검토 → 안전성 확인 → 전달
```

각 단계가 앞 단계의 결과를 필요로 하기 때문에 한 번에 처리하기 어렵다. 그 결과 아동은 한 문장을 받기 위해 약 15초 정도 기다려야 하고, 느린 경우에는 18초 이상 기다리게 된다.

아동 대상 대화에서는 이 정도 대기 시간이 길게 느껴질 수 있다. 따라서 이번 주에는 새로운 기능을 추가하기보다, 이 대기 시간을 줄이거나 기다리는 동안에도 역할극에 계속 참여하고 있다고 느낄 수 있게 만드는 데 집중한다.

## 6. 개선을 위해 검토할 후보

현재는 캐릭터 응답을 보내기 전에 여러 분석과 확인을 모두 끝내야 한다. 응답 지연을 줄이기 위해 다음과 같은 후보를 검토할 수 있다. 아직 어느 한 가지 방법을 결정한 상태는 아니다.

### 후보 1) 일반 응답과 마스코트 개입을 나누기

평소에는 캐릭터가 먼저 대화를 이어가고, 마스코트는 뒤에서 아동이 어려움을 겪고 있는지 확인하는 방식이다.

```text
아동 입력
  ├─ 일반 응답: 캐릭터가 대화를 이어가고 안전성 확인 후 전달
  └─ 별도 분석: 마스코트가 뒤에서 아동의 어려움 여부를 확인
                  → 정말 도움이 필요할 때만 힌트 제공
```

마스코트는 같은 부분에서 여러 번 막히거나, 아동이 직접 도움을 요청하는 경우처럼 정말 필요한 때만 개입한다. 일반적인 대화에서는 마스코트 분석을 기다리지 않아도 된다는 장점이 있다.

다만 분석 결과가 늦게 도착했을 때 이미 다음 대화가 진행되고 있을 수 있으므로, 힌트를 언제 보여줄지 정하는 작업이 필요하다. 캐릭터 응답의 안전성 확인은 이 방식에서도 유지해야 한다.

### 후보 2) AI가 처리하는 단계와 호출 횟수 줄이기

현재 여러 단계로 나뉜 상황 분석, 응답 작성, 응답 검토 중 일부를 합치거나, 간단한 상황에서는 일부 단계를 생략하는 방법이다.

- 간단한 대화는 별도 상황 분석 없이 응답하기
- 응답 작성과 일부 분석을 한 번에 처리하기
- 위험도가 낮은 상황과 높은 상황의 검증 단계를 다르게 적용하기
- AI의 사고 수준이나 출력량을 줄여 처리 시간 단축하기

이 방법은 가장 직접적으로 시간을 줄일 수 있지만, 안전성과 응답 품질이 떨어질 가능성이 있어 비교 테스트가 필요하다.

### 후보 3) 자주 나오는 상황을 미리 준비하기

자주 반복되는 상황이나 기본 응답을 미리 준비해두고, 꼭 AI가 새로 작성할 필요가 없는 경우에는 준비된 응답을 사용하는 방식이다.

예를 들어 인사, 간단한 확인, 대기 안내처럼 위험도가 낮고 반복되는 상황은 미리 준비한 대사와 행동을 사용할 수 있다. 이 경우 AI 호출 횟수를 줄일 수 있지만, 대화가 부자연스럽게 반복되지 않도록 관리해야 한다.

### 후보 4) 기다리는 동안 역할극의 몰입 유지하기

실제 처리 시간이 바로 줄지 않더라도, 기다리는 시간이 지루하게 느껴지지 않도록 하는 방법이다.

- 캐릭터가 생각하거나 행동하는 짧은 애니메이션
- 캐릭터가 다음 행동을 준비하는 모습
- 역할극 상황에 맞는 짧은 대기 연출
- 응답이 준비되면 대사와 캐릭터 표정·행동을 함께 보여주기
- 검증되지 않은 AI 문장은 미리 보여주지 않고, 안전하게 준비된 연출만 사용하기

이 방법은 실제 응답 시간을 줄이는 해결책은 아니지만, 사용자가 느끼는 대기 시간을 줄이는 보완책이 될 수 있다.

### 후보 비교 시 확인할 점

- 응답 준비 시간이 실제로 줄어드는가
- 안전성 확인 수준이 유지되는가
- 캐릭터와 마스코트의 역할이 자연스럽게 이어지는가
- 뒤늦게 도착한 분석 결과가 잘못된 순간에 노출되지 않는가
- 구현 난이도와 유지보수 부담이 감당 가능한가

## 7. 현재 POC의 한계

- 현재 테스트가 통과한 것은 정해둔 상황에서 코드 흐름이 예상대로 동작한다는 의미다. 실제 AI가 모든 상황을 잘 이해한다는 뜻은 아니다.
- 실제 대화가 자연스럽고 교육적으로 적절한지는 아직 사람의 평가가 필요하다.
- 현재 테스트 사례가 많지 않기 때문에 응답 시간 결과도 참고용으로만 보고 있다.
- 현재는 명령줄에서 실행하는 형태이며, 실제 화면과 연결되지는 않았다.
- 실제 서비스에 필요한 데이터 저장, 재시도, 안정적인 메시지 전달은 아직 구현하지 않았다.

## 8. 이번 주 남은 작업

이번 주에는 아래 후보들을 비교해 응답 지연 문제에 가장 적합한 방향을 정한다.

1. 현재 구조의 응답 시간을 기준값으로 기록한다.
2. 일반 응답·마스코트 분리, 호출 단계 축소, 사전 응답 활용, 대기 UX 등의 후보를 정리한다.
3. 각 후보의 예상 효과와 안전성·구현 난이도를 비교한다.
4. 가능성이 높은 후보를 동일한 테스트 사례로 실험한다.
5. 개선 전후의 응답 시간, 안전성, 대화 자연스러움을 비교한다.
6. 비교 결과를 바탕으로 다음 구현 방향을 결정한다.

## 9. 이번 주 작업의 의미

이번 주에는 단순히 문서만 작성한 것이 아니라, 실제로 대화 에이전트의 핵심 흐름을 코드로 만들고 여러 상황에서 테스트했다. 그 결과 기본적인 역할극 처리와 안전성 확인은 동작하는 것을 확인했다.

동시에 현재 구조에서는 한 번의 응답을 만들기 위해 여러 단계를 순서대로 기다려야 한다는 문제도 확인했다. 이번 주에는 일반 대화 응답과 마스코트의 학습 개입 분리, AI 호출 단계 축소, 자주 쓰는 응답의 사전 준비, 대기 중 몰입 유지 등 여러 후보를 비교해 가장 적절한 개선 방향을 정할 예정이다.
