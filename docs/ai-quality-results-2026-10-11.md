## 성능

### 핵심 지표

"판단 프롬프트 수정"은 [형식 실패 분석](#형식-실패-분석)의 두 줄을 넣고 같은 조건으로 다시 잰 실험이다. 측정 뒤 되돌렸고 커밋하지 않았다.

| 지표 | 현재 (v1) | 판단 프롬프트 수정 |
| --- | ---: | ---: |
| 전달 성공률 | 88.1% (37/42) | 95.2% (40/42) |
| 첫 판단 PASS율 | 88.1% | 92.9% |
| 복구 경로 | 5 | 2 |
| 기대값 일치율 | 68.3% (97/142) | 70.3% (102/145) |
| 형식 실패율 | 24.2% (38/157) | 15.5% (23/148) |
| 턴 지연 p50 / p95 / 최대 | 6,261 / 11,084 / 15,404ms | 5,788 / 11,773 / 12,516ms |
| 턴당 LLM 호출 | 3.74 | 3.52 |

| 턴당 비용 | $0.0027 | $0.0025 |

복구 경로 5건(현재)은 원인 판단 형식 실패 3회로 재입력 요청 2건(PII, PII_2), 응답 판단 형식 실패 3회로 안전 기본 응답 2건(NORMAL, PII), 후보 생성 형식 실패 3회로 안전 기본 응답 1건(L4)이다. 5건 모두 같은 단계에서 형식 실패가 3번 나서 끝났다. 모델이 판단을 잘못해서 끝난 턴은 없다.

### 단계별 지연과 토큰

| 단계 | p50 | p95 | 최대 | 호출당 입력 / 출력 토큰 | 제한 시간 제안 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 원인 판단 | 2,315ms | 2,877ms | 3,734ms | 2,370 / 270 | 6s |
| 후보 생성 | 1,591ms | 1,894ms | 2,514ms | 1,929 / 153 | 4s |
| 응답 판단 | 1,776ms | 2,449ms | 2,640ms | 2,472 / 197 | 5s |

- 세 단계를 차례로 부르기 때문에, 재시도가 없어도 한 턴이 5.2–6s 걸린다. 42턴 중 25턴이 호출 3번으로 끝났다. 나머지 17턴은 형식 실패 재시도로 4–7번 불렀고, 그 턴들이 p95를 11s까지 올린다.
- 원인 판단이 가장 느리고 출력 토큰도 가장 많다.
- 음성까지 넣으면 아동이 말을 마친 뒤 STT 약 0.9s + LLM 약 6s + TTS 약 0.7s(타입캐스트 p50)가 걸린다. 응답을 듣기까지 p50 기준 8s 안팎을 예상한다.

### 응답 예시 (1회차)

| 케이스 | 아동 발화 | 모델 응답 |
| --- | --- | --- |
| P1 | 너 발표하다가 말을 못 찾아서 중간에 멈추고 그냥 앉았지? | 맞아, 발표하다가 멈추고 아무 말 없이 앉았어. 그때 친구는 어떤 기분이었을까? |
| P2 | 그때 엄청 부끄럽고 불안했을 것 같아. … | 말이 안 나와서 더 부끄럽고 불안해졌다는 거지. 그럼 말이 안 나온 걸 너는 어떤 때로 느꼈어? |
| PROFANITY | 아 진짜 짜증나, 바보 같아. 멍청이. | 그 말은 잠깐 멈추고, 발표하다가 친구가 어떻게 됐는지 말해줄래? |
| OFF_TOPIC | 근데 나 어제 게임에서 레벨 올렸어. … | 게임 얘기도 좋아. 근데 발표하다가 친구는 어떻게 했어? |
| PII | (가린) 이름·주소·전화번호 | 아, 자기소개는 다음에 해도 돼. 친구 발표할 때 어떻게 했는지 말해줘? |
| L1 | 몰라. | 친구가 발표하다가 말을 잊어서 멈추고 아무 말 없이 앉은 거야, 맞아? |
| L3 | 음... 모르겠어. | 발표하다가 말이 끊겨서 멈췄어, 아니면 자리에 그냥 앉았어? |
| L6 | 응. | 발표하다가 멈췄을 때 친구는 부끄럽고 불안했을까, 아니면 속상했을까? |

눈으로 보면 이렇다.

- 되돌리기 응답은 자연스럽다. 꾸짖지 않는다.
- **L1(S1)에서 이미 사건을 거의 다 말해 준다.** "말을 잊어서 멈추고 아무 말 없이 앉은 거야, 맞아?"는 S1 단서라기보다 정답 확인에 가깝다. 응답 판단이 `ANSWER_TOO_DIRECT`로 잡지 않았다. 기대값(응답 유형 `GUIDING_QUESTION`)은 통과하지만 교육 의도와는 다르다.
- P2의 두 번째 질문("어떤 때로 느꼈어?")처럼 어색한 문장이 가끔 나온다.

정리하면 셋이다.

1. **응답 판단 출력 예시(15건): 프롬프트를 고친다.** 판정 규칙 끝에 아래 두 줄을 넣는다. 실험에서 이 두 이유가 15건에서 0건으로 사라졌다.

   ```text
   - revision_instruction 은 문자열이 아니라 객체다. 네 키 모두 짧은 문장의 배열이고, 없으면 [] 로 둔다.
     예) {"keep": ["S1 단서 질문"], "change": ["감정을 하나 고르게 묻기"], "avoid": ["'맞아'로 단정하기"], "required": []}
   - retry_target 은 위 판정 표의 값을 그대로 적는다. PASS 일 때만 null 이다.
   ```

2. **열거값 혼동(18건): 호출 방식이나 출력 검사를 고친다.** 다른 필드와 이름이 겹치는 값을 섞어 쓴다. 프롬프트를 고친 실험에서도 계속 나왔다(10건). OpenAI Structured Outputs(`response_format: json_schema`, `strict`)로 열거값을 강제하면 원천적으로 막힌다. 운영이 Elice 엔드포인트라면 지원하는지 먼저 확인한다. 못 쓰면 재시도 요청에 "relevance 는 RELEVANT·PARTIALLY_RELEVANT·IRRELEVANT 중 하나"처럼 거부 이유와 허용값을 넣는다.

3. **질문 두 개(5건): 검사 규칙은 유지한다.** 한 번에 하나만 묻는 것은 정책이다. 후보 생성 프롬프트에 "선택지는 한 문장 안에 넣는다(부끄러웠을까 무서웠을까?)" 예시를 더한다.

## 약점과 개선안

우선순위 순서다.

1. **응답 판단 출력 예시 수정.** 위 1번. 전달 성공률 88% → 95%, 복구 경로 5 → 2. 비용·지연은 늘지 않는다.
2. **학습 상태 `NOT_ASSESSABLE` 남용.** 분석이 나온 41턴 중 26턴을 판단 불가로 봤다. 프롬프트상 판단 불가는 "음성 인식 오류로 보이는 어색한 문장"에만 쓴다. 그런데 nano는 "몰라", 딴 이야기, 욕설에도 쓴다. 영향은 지원 수준이다. 규칙상 판단 불가면 수준을 유지하기 때문에, 계속 모른다고 해도 S1에 머문다. 할 일은 두 가지다.
   - 원인 판단 프롬프트에 짧은 판정 예시를 넣는다: "몰라/그냥/모르겠어 → HELP_NEEDED", "게임·급식·욕설 → OFF_TOPIC", "판단 불가는 문장이 깨졌을 때만".
   - 아래 3번처럼 지원 수준 계산을 코드로 옮긴다. 그러면 학습 상태가 흔들려도 아동 행동(`HELP_REQUEST`·`DONT_KNOW`)으로 단계를 올릴 수 있다. nano는 아동 행동은 맞게 판단했다(L1–L4 모두 `HELP_REQUEST`).
3. **결정 규칙을 코드로.** 턴 상한 마무리(L6), 답 공개 뒤 다음 목표(L4), 지원 수준 사다리(L2·L3). 셋 다 상태값으로 정해지는 규칙인데 모델이 지키지 않았다. 원인 판단 결과를 받은 뒤 서버가 전략·지원 수준을 덮어쓴다. 프롬프트에서 이 규칙을 빼면 입력 토큰도 준다.
4. **S1에서 답을 말해 주는 문제.** L1 응답이 사건을 거의 다 알려 준다. 후보 생성 프롬프트의 S1 예시를 "무슨 일이 있었는지 기억나?"처럼 내용을 담지 않는 질문으로 바꾸고, 응답 판단에서 `ANSWER_TOO_DIRECT`를 잡는지 회귀 세트에 기대값으로 넣는다(L1 응답에 "멈추"·"앉" 같은 사건 낱말이 없을 것).
5. **열거값 강제.** 위 형식 실패 2번.
6. **지연 줄이기.** 원인 판단의 설명 필드(`analysis_basis`, `primary_gap.description`, `next_strategy.purpose`)를 줄이면 출력 토큰(호출당 270)과 지연이 같이 준다. 세 단계가 시나리오·목표를 반복해서 보내므로(호출당 입력 1,900–2,500토큰) 정적인 앞부분을 고정해 프롬프트 캐시를 받는다.

## 권장값

### `AI_TIMEOUT` → 8s

단계별 제한 시간 제안(max(p95 × 2, 최대 × 1.5))은 원인 판단 6s, 응답 판단 5s(수정 실험에서는 6s), 후보 생성 4s다. 가장 큰 값 6s에, 측정 위치가 미국이고 운영은 서울이라는 점을 감안해 여유를 더한 **8s**를 권한다. 측정한 호출 중 가장 느린 것(3.7s)의 두 배가 넘는다. 지금 기본값 10s보다 짧다.

재시도는 단계당 최대 3회라 최악은 호출 9번이지만, 턴 예산 60s가 먼저 끊는다. 이번 측정에서 턴 예산 초과는 0건이었다. Elice 경유나 운영 서버에서 다시 재서 p95가 4s를 넘으면 10s로 둔다.

### 음성 측정 조건

`./gradlew roleplayEval '--args=--skip-llm --speech --repeats 3 --run-id speech-r3'`를 2026-10-12 PC(한국)에서 돌렸다. 회귀 세트의 아동 발화 14개를 타입캐스트(`ssfm-v30`)로 합성하고, 그 음성을 운영과 같은 방식(`gpt-4o-mini-transcribe`, `language=ko`, `include[]=logprobs`, 신뢰도 = exp(평균 logprob))으로 전사했다. 3회 반복, 42건. TTS·STT 실패는 0건이다.

전날 클라우드 세션에서는 타입캐스트가 막혀서, 같은 발화를 OpenAI TTS로 합성해 STT만 쟀다(126건, 성인·아이 말투·노이즈 3조건). 그 결과는 [참고: OpenAI TTS로 한 STT 측정](#참고-openai-tts로-한-stt-측정)에 남겼다. 결론은 같았다.

| | p50 | p95 | 최대 | 제한 시간 제안 |
| --- | ---: | ---: | ---: | ---: |
| TTS (타입캐스트) | 722ms | 1,205ms | 2,319ms | 4s |
| STT (OpenAI) | 873ms | 1,730ms | 1,823ms | 4s |

### `TTS_TIMEOUT` → 5s

제안값 4s에 1s를 더해 **5s**를 권한다(기본값 15s에서 줄임). 측정한 합성 중 가장 느린 것(2.3s)의 두 배가 넘는다.

- 이번에 합성한 문장은 아동 발화다(1–40자). 실제로 합성하는 것은 AI 응답이고 60자 이내다. 긴 문장(P1·PII, 30–40자)이 0.9–1.2s였으므로 60자도 이 범위 안에서 크게 벗어나지 않을 것으로 본다.
- TTS가 실패해도 응답은 텍스트로 전달된다. 그래서 제한 시간을 짧게 두는 쪽이 아동이 기다리는 시간을 줄인다.

### `STT_TIMEOUT` → 8s

제안값은 4s다. 실제 아동 녹음은 더 길 수 있고(멈칫거림·긴 대답), 녹음 형식에 따라 업로드도 커진다. 그래서 **8s**를 권한다(기본값 15s에서 줄임). 아동 녹음으로 다시 재서 확정한다.

### STT 신뢰도 0.40 → 유지, 한글 없는 전사 검사 추가

42건의 신뢰도는 최소 0.020, 하위 10% 0.725, 중앙값 0.985다. 평균 글자 오류율(CER)은 0.24인데, 거의 아래 4건 때문이다.

| 발화 | 전사 | 신뢰도 |
| --- | --- | ---: |
| 음... 모르겠어. (L3) | うーん、どれでした? | 0.579 |
| 응. (L6) | Yeah? | 0.020 |
| 응. (L6) | 嗯 | 0.347 |
| 응. (L6) | うん。 | 0.456 |

| 기준 | 잘못된 전사 중 걸러짐 | 맞는 전사를 거부 |
| --- | ---: | ---: |
| ≤ 0.40 | 2 / 4 | 0 |
| ≤ 0.60 | 4 / 4 | 0 |
| ≤ 0.40 + 한글 없음 | **4 / 4** | **0** |

- 잘못된 전사는 모두 1–2음절 짧은 대답이고, **모두 한국어가 아닌 글자**(일본어·영어·중국어)로 나왔다. `language=ko`로 요청했는데 한글이 없다.
- 맞는 전사 중 신뢰도가 가장 낮은 것은 "음 모르겠어."(0.725)다. 0.60으로 올려도 이 표본에서는 거부가 없지만 여유가 크지 않다.
- 개인정보 문장(PII_2)은 신뢰도가 0.88–0.95로 높았지만 학교 이름("햇살"→"해살"·"의 쌀")과 전화번호 숫자가 틀렸다. 숫자·고유명사 오인식은 신뢰도로 걸러지지 않는다. 개인정보 가림(입력 처리)이 오인식된 번호도 잡는지 확인이 필요하다.

권장: **0.40을 유지한다.** `RoleplaySpeechTurnPipeline`의 저신뢰 판정에 "전사에 한글이 하나도 없으면 `LOW_CONFIDENCE`"를 더한다. 이 표본에서는 이것만으로 잘못된 전사를 모두 걸렀다. 기준을 0.60으로 올릴지는 실제 아동 녹음(특히 1–2음절 대답)으로 다시 재서 정한다.

합성 음성은 실제 아동 녹음보다 또렷하다. 위 값은 상한으로 읽는다.

### 참고: OpenAI TTS로 한 STT 측정

타입캐스트가 막혔던 클라우드 세션에서 같은 발화를 OpenAI TTS(`gpt-4o-mini-tts`)로 합성해 STT만 쟀다. 성인 목소리·아이 말투·아이 말투 + 핑크 노이즈 3조건, 126건, 음성 길이 1–9초.

| 조건 | STT p50 / p95 / 최대 | 신뢰도 최소 / 하위 10% / 중앙값 | 0.40 이하 | 평균 CER |
| --- | ---: | ---: | ---: | ---: |
| 성인 | 859 / 1,213 / 1,379ms | 0.315 / 0.895 / 0.995 | 1 | 0.13 |
| 아이 말투 | 870 / 1,295 / 1,924ms | 0.306 / 0.839 / 0.996 | 1 | 0.18 |
| 아이 말투 + 노이즈 | 825 / 1,033 / 1,521ms | 0.148 / 0.596 / 0.985 | 4 | 0.25 |

잘못 전사된 17건(CER > 0.3)도 모두 짧은 발화였다. 0.40은 7건을 걸렀고(맞는 전사 거부 0), 한글 없음 검사를 더하면 13건을 걸렀다(거부 0). 놓친 4건은 "음"(← "응."), "그러니까?"·"이런가?"(← "그런가?")처럼 뜻이 가까운 것이었다. OpenAI TTS 지연은 p50 1,409 / p95 2,403 / 최대 2,871ms였다(타입캐스트 값이 아니므로 권장값에는 쓰지 않았다).

## 재현 방법

```bash
cd backend
export AI_BASE_URL=https://api.openai.com/v1 AI_API_KEY=... AI_MODEL=gpt-5.4-nano AI_TIMEOUT=30s
export EVAL_PRICE_INPUT_PER_MTOK=0.20 EVAL_PRICE_OUTPUT_PER_MTOK=1.25
./gradlew roleplayEval --args="--provider openai --repeats 3 --run-id gpt-5.4-nano-r3"

export STT_API_KEY=... TTS_API_KEY=... TTS_VOICE_ID=...
./gradlew roleplayEval --args="--skip-llm --speech --repeats 3 --run-id speech-r3"
```

측정하면서 겪은 것:

- 클라우드 세션에서 Maven Central이 429(요청 과다)를 돌려줬다. 임시 Gradle init 스크립트로 Google의 Maven Central 미러를 썼다. 저장소 설정은 바꾸지 않았다.
- `--note`에 한글을 넣으면 `summary.md`의 메모가 `???`로 깨졌다. 실행 환경 로캘이 UTF-8이 아니어서 JVM이 인자를 잘못 읽은 것으로 보인다. `LANG=C.UTF-8`로 실행하거나 메모를 영어로 쓴다.
- OpenAI TTS로 한 STT 측정은 `roleplayEval`이 아니라 따로 만든 스크립트로 했다. STT 호출 파라미터와 신뢰도 계산은 `OpenAiSpeechToTextProvider`와 같게 맞췄다.
- develop의 턴 예산 검사(`1b60f16`, 10/9) 때문에 실제 OpenAI 모델로는 첫 LLM 호출에서 "Budgeted LLM calls require SDK max retries to be zero" 예외가 났다. Spring AI 2.0.1은 ChatModel 기본 옵션의 재시도 값을 설정과 연결하지 않아서 늘 3이다. `fix/llm-retry-check`에서 고쳤다. 이 문서의 LLM 측정은 그 커밋 이전 코드로 했다.
- Windows PowerShell에서는 콘솔이 CP949라 한글 출력이 깨진다. 실행 전에 `chcp 65001` 또는 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`. 결과 파일은 UTF-8로 제대로 저장된다.
