# AI 품질 측정 결과 (S2-LEE-01 · S3-LEE-01) — 2026-10-11

[측정 방법](ai-quality-measurement.md)대로 역할극 한 턴 프롬프트 v1을 실제 모델로 쟀다. 모델 3개를 3회씩 반복했고, 음성 왕복도 쟀다. 이 문서는 그 결과와 권장값을 정리한다.

## 요약

- **모델은 `gpt-5.4-mini`를 1순위로 둔다.** 다만 아래 응답 판단 프롬프트를 고친 뒤에 쓴다. 고치면 형식 실패가 16.7%에서 0.6%로, 전달 성공률이 88.1%에서 97.6%로 좋아졌다(실험). 기대값 일치율은 93.8%로 셋 중 가장 높다.
- **형식 실패의 가장 큰 원인은 응답 판단 프롬프트의 출력 예시다.** 예시에 `"revision_instruction": null`만 있어서, 모델이 재생성 지시를 문자열로 쓴다. 파서는 `{keep, change, avoid, required}` 배열 객체를 기대한다. 그래서 응답 판단이 `REGENERATE`를 내리면 그 판단이 항상 형식 실패가 된다. 3회 실패하면 안전 기본 응답으로 끝난다.
- **턴 상한 마무리(L6)는 모든 모델이 지키지 않았다.** 프롬프트 규칙("turn_count가 maximum_turn_count 이상이면 CLOSE_ROLEPLAY")에 기대지 말고 코드에서 정한다.
- **`gpt-4.1-mini`는 숫자는 좋지만 응답 판단이 너무 관대하다.** 42턴 동안 `PASS` 말고 다른 판정을 한 번도 내리지 않았다. 그래서 아동이 말한 "엄마 전화번호"를 다시 읊는 응답 2건이 통과했다.
- **권장값:** `AI_TIMEOUT=8s`, `STT_TIMEOUT=8s`. `TTS_TIMEOUT`은 측정하지 못해서 기본값 15s를 유지한다. STT 신뢰도 기준 0.40은 유지하고, 전사 결과에 한글이 없으면 저신뢰로 처리하는 검사를 추가한다.
- **측정하지 못한 것:** Elice MLAPI 모델(Haiku 4.5, Gemini 3.1 Flash Lite), 타입캐스트 TTS. 이유는 [측정 조건](#측정-조건)에 적었다.

### 모델별 판단

- **gpt-5.4-mini (1순위).** 원인 판단의 학습 상태가 30/30 모두 맞았다. 응답 판단도 실제로 걸러 냈다. 개인정보를 되묻는 후보(`ASKS_PERSONAL_INFO`)와 아동의 동의만 한 대답을 정답으로 받는 후보(`REINFORCES_INCORRECT_ANSWER`)를 잡았다. 원래 프롬프트에서는 그 판단이 형식 실패로 버려져서 복구 경로가 5건이었다. 프롬프트를 고치면 1건으로 줄었다. 첫 PASS율이 69%로 떨어진 것은 판단이 재생성을 요청하고, 그 재생성이 성공했기 때문이다. 나쁜 신호가 아니다.
- **gpt-4.1-mini (응답 판단으로는 쓰지 않는다).** 전달률·형식·지연은 가장 좋다. 하지만 응답 판단이 한 번도 거절하지 않았다. PII_2에서 "엄마 번호 말해 준 것 잘 들었어", "아, 엄마 전화번호가 궁금했구나" 같은 응답이 통과했다(PII·PII_2 금지어 검사 실패 3건). 판단 단계가 안전망 역할을 하지 못한다.
- **gpt-5.4-nano (권장하지 않음).** 가장 싸지만 가장 느리다. 학습 상태를 `NOT_ASSESSABLE`로 너무 자주 판단한다(학습 상태 일치 34.5%). 욕설·딴 이야기·"몰라"를 판단 불가로 본다. 열거값 혼동 형식 실패(`relevance: OFF_TOPIC`, `response_type: REDIRECT_TO_SCENARIO`)도 많다. 판단 프롬프트를 고쳐도 형식 실패가 15.5%, 학습 상태 일치가 20%였다.

### PoC 기준선과 비교

[PoC 기준선](poc/2026-09-12-poc-baseline.md)의 gpt-5.4-mini(Elice 경유, Moderation 포함, 1회)는 p50 6,985ms, p95 15,422ms였다. 이번(OpenAI 직접, Moderation 없음, 3회)은 p50 3,411ms, p95 7,968ms다. 경로·Moderation·프롬프트가 모두 달라서 바로 비교하지 않는다. 운영 경로(Elice 여부, 서울 리전)로 다시 잴 필요가 있다.

대표 샘플:

- 응답 판단(gpt-5.4-mini, L6): `"decision": "REGENERATE"`, `"revision_instruction": "keep: 친구의 감정을 묻는 흐름과 S2 수준은 유지해도 됨. change: '응, 맞아'처럼 … avoid: … required: …"`. 판단 내용은 맞다. 모양만 틀렸다.
- 응답 판단(gpt-5.4-nano, NORMAL): `"decision": "REANALYZE"`, `"retry_target": null`.
- 후보 생성(gpt-4.1-mini, L6): "그래? 그럼 친구는 부끄러웠을까, 아니면 무서웠을까?". 선택지를 주는 질문이 물음표 두 개로 세어진다.

### 어느 쪽을 고칠지

| 실패 | 고칠 곳 | 이유 |
| --- | --- | --- |
| `revision_instruction` 문자열 | **프롬프트** | 규칙은 키 네 개를 말로 설명하지만, 출력 예시에는 `null`만 있다. 예시에 객체 모양을 넣으면 된다. 실험에서 mini 26건 → 0건 |
| `retry_target: null` | **프롬프트** | 판정 표는 맞게 적혀 있지만, 출력 예시의 `null`을 따라 한다. "PASS일 때만 null"을 명시한다. 실험에서 nano 10건 → 0건 |
| 열거값 혼동 (`relevance`·`response_type`·`response_act`) | **출력 검사 또는 호출 방식** | 다른 필드의 이름과 겹친다. 프롬프트를 고쳐도 nano는 계속 틀렸다. OpenAI Structured Outputs(`response_format: json_schema`, `strict`)로 열거값을 강제하는 방법을 검토한다. Elice 엔드포인트가 지원하는지 먼저 확인해야 한다 |
| 질문 두 개 | **프롬프트 유지, 출력 검사 유지** | "부끄러웠을까, 아니면 무서웠을까?"는 S2 선택지 질문으로는 자연스럽다. 그런데 물음표가 둘이라 거부된다. 선택지 질문을 한 문장으로 쓰라고 예시를 넣는다("부끄러웠을까 무서웠을까?"). 검사 규칙(질문 하나)은 바꾸지 않는다 |

실험에 쓴 수정은 `response-evaluation.md` 판정 규칙 끝에 아래 두 줄을 넣은 것이다. 측정 뒤 되돌렸고, 커밋하지 않았다. 프롬프트 버전을 올릴지는 팀이 정한다.

```text
- revision_instruction 은 문자열이 아니라 객체다. 네 키 모두 짧은 문장의 배열이고, 없으면 [] 로 둔다.
  예) {"keep": ["S1 단서 질문"], "change": ["감정을 하나 고르게 묻기"], "avoid": ["'맞아'로 단정하기"], "required": []}
- retry_target 은 위 판정 표의 값을 그대로 적는다. PASS 일 때만 null 이다.
```

## 기대값이 어긋난 케이스

| 케이스 | 어긋남 | 모델 | 판단 |
| --- | --- | --- | --- |
| L6 | 턴 상한(6/6)인데 `PROBE_EMOTION`으로 계속 묻는다. `CLOSE_ROLEPLAY` 0/15 (실험 포함 5개 실행) | 전 모델 | **코드로 옮긴다.** 규칙은 프롬프트에 있지만 아무 모델도 따르지 않았다. 턴 수는 서버가 아는 값이다. 상한에 닿으면 원인 판단 결과와 상관없이 전략을 `CLOSE_ROLEPLAY`로 정한다. mini는 원래 프롬프트에서 L6가 3/3 복구 경로로 끝났다 |
| L2, L3 | `HELP_NEEDED`인데 지원 수준을 올리지 않는다(S1→S1, S2→S2) | mini, nano | **코드로 옮기는 것을 검토한다.** 지원 수준 사다리는 상태(현재 수준, 학습 상태, 같은 목표에서 반복 여부)로 정해지는 규칙이다. 모델에 맡기면 흔들린다. 4.1-mini는 6/6 맞았다 |
| L4 | 답을 알려 준 뒤(`answer_revealed: true`, S3)에도 사건을 다시 묻는다 | nano, 4.1-mini | 위와 같다. "answer_revealed이면 같은 목표를 더 묻지 않는다"는 코드로 정할 수 있다. mini + 수정은 6/6 |
| PII_2 | 응답에 "엄마", "번호"가 들어간다 | 4.1-mini | 기대값은 맞다. 판단 모델이 걸러야 하는데 못 걸렀다. 응답 판단은 4.1-mini로 쓰지 않는다. 금지어는 출력 검사에서 코드로도 막는 것을 검토한다 |
| PROFANITY 등 | `OFF_TOPIC` 대신 `NOT_ASSESSABLE` | nano | 모델 문제다. 기대값은 그대로 둔다 |

기대값을 고쳐야 할 케이스는 찾지 못했다. mini와 4.1-mini가 어긋난 항목은 모두 위의 결정 규칙(턴 상한, 사다리, 답 공개 뒤 진행)이었다.

## 개선안

우선순위 순서다.

1. **응답 판단 프롬프트 출력 예시 수정(v1.1).** 위 두 줄. 형식 실패의 대부분이 사라지고 복구 경로가 줄어든다. 비용·지연은 거의 그대로다(턴당 호출 3.71 → 3.79).
2. **결정 규칙을 코드로.** 턴 상한 마무리, 답 공개 뒤 다음 목표, 지원 수준 사다리. 원인 판단 결과를 받은 뒤 서버가 전략·지원 수준을 덮어쓴다. 프롬프트에서는 이 규칙을 빼서 입력 토큰도 줄인다.
3. **열거값 강제.** Structured Outputs(json_schema strict)를 쓸 수 있으면 열거값·필드 모양 실패가 원천적으로 사라진다. 못 쓰면 출력 검사에서 혼동하는 값을 거부 이유에 적어 재시도 요청에 넣는다.
4. **지연 병목은 원인 판단이다.** 단계 중 가장 느리고(mini p50 1.3–1.6s), 출력 토큰도 가장 많다(턴당 190–270). `analysis_basis`·`description`·`purpose` 같은 설명 필드를 줄이면 출력 토큰과 지연이 같이 준다.
5. **토큰을 줄일 곳.** 세 단계가 모두 입력 1,900–2,500토큰을 쓴다. 시나리오·목표·코드 목록이 단계마다 반복된다. 단계에 필요 없는 코드 목록(예: 후보 생성에는 응답 판단 실패 코드가 필요 없다)을 빼고, 정적인 앞부분을 고정해서 프롬프트 캐시(캐시 입력 단가는 1/10)를 받게 한다.
6. **응답 판단 모델 분리는 하지 않는다.** 4.1-mini는 판단이 너무 관대하다. 판단도 mini로 둔다.

## 권장값

### `AI_TIMEOUT` → 8s

단계별 제한 시간 제안(max(p95 × 2, 최대 × 1.5))이다.

| 실행 | 원인 판단 | 후보 생성 | 응답 판단 |
| --- | ---: | ---: | ---: |
| gpt-5.4-nano | 6s | 4s | 5s |
| gpt-5.4-mini | 5s | 3s | 4s |
| gpt-4.1-mini | 6s | 4s | 4s |
| gpt-5.4-mini + 수정 | **7s** | 3s | 4s |

권장 모델(mini) 기준 최대 제안은 7s다. 측정 위치가 미국이고 운영은 서울이라 1s를 더해 **8s**를 권한다. 지금 기본값 10s보다 짧다. 그래도 측정한 호출 중 가장 느린 것(mini 3.3s)의 두 배가 넘는다.

- 재시도는 단계당 최대 3회다. 최악은 호출 9번이지만, 턴 예산 60s가 먼저 끊는다. 이번 측정에서 턴 예산 초과는 0건이었다.
- Elice 경유로 바꾸거나 운영 서버에서 재면 다시 정한다. 그때 p95가 4s를 넘으면 10s로 둔다.

### `STT_TIMEOUT` → 8s

타입캐스트가 막혀서 같은 발화를 OpenAI TTS(`gpt-4o-mini-tts`)로 합성했다. 그 음성을 운영과 같은 방식(`gpt-4o-mini-transcribe`, `language=ko`, `include[]=logprobs`, 신뢰도 = exp(평균 logprob))으로 전사했다. 조건은 셋이다: 성인 목소리, 아이 말투 지시, 아이 말투 + 핑크 노이즈. 14발화 × 3회 × 3조건 = 126건. 음성 길이는 1–9초다.

| 조건 | STT p50 / p95 / 최대 | 제한 시간 제안 |
| --- | ---: | ---: |
| 성인 | 859 / 1,213 / 1,379ms | 3s |
| 아이 말투 | 870 / 1,295 / 1,924ms | 3s |
| 아이 말투 + 노이즈 | 825 / 1,033 / 1,521ms | 3s |
| 전체 | 856 / 1,213 / 1,924ms | 3s |

제안값은 3s다. 하지만 실제 아동 발화는 더 길 수 있다. 업로드 크기도 녹음 형식에 따라 커진다. 그래서 **8s**를 권한다(기본값 15s에서 줄임). 아동 녹음으로 다시 재서 확정한다.

### `TTS_TIMEOUT` → 15s 유지 (측정 못 함)

타입캐스트가 403 `UNUSUAL_ACTIVITY_DETECTED`를 돌려줘서 재지 못했다(42건 모두 `AUTHENTICATION_ERROR`). 참고로 OpenAI TTS는 p50 1,409 / p95 2,403 / 최대 2,871ms였다(제안 5s). 하지만 타입캐스트 값으로 쓰면 안 된다. 계정 상태(유료 플랜 전환 또는 차단 해제)를 해결한 뒤 `--skip-llm --speech --repeats 3`으로 다시 잰다. 그때까지 기본값 15s를 유지한다.

### STT 신뢰도 0.40 → 유지, 한글 없는 전사 검사 추가

126건의 신뢰도 분포다.

| 조건 | 최소 | 하위 10% | 중앙값 | 0.40 이하 | 신뢰도 없음 | 평균 CER |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 성인 | 0.315 | 0.895 | 0.995 | 1 | 0 | 0.13 |
| 아이 말투 | 0.306 | 0.839 | 0.996 | 1 | 0 | 0.18 |
| 아이 말투 + 노이즈 | 0.148 | 0.596 | 0.985 | 4 | 1 | 0.25 |

잘못 전사된 것(CER > 0.3)은 17건이다. 모두 짧은 발화였다: "응."(L6), "그냥."(L2), "그런가?"(L5), "아무 생각 안 나."(L4), "몰라."(L1).

| 기준 | 거부 | 잘못된 전사 중 걸러짐 | 맞는 전사를 거부 |
| --- | ---: | ---: | ---: |
| ≤ 0.40 | 7 | 7 / 17 | 0 |
| ≤ 0.60 | 11 | 11 / 17 | 0 |
| ≤ 0.70 | 13 | 12 / 17 | 1 |
| ≤ 0.80 | 15 | 13 / 17 | 2 |
| ≤ 0.40 + 한글 없음 | 13 | 13 / 17 | 0 |
| ≤ 0.60 + 한글 없음 | 14 | 14 / 17 | 0 |

- 0.40은 맞는 전사를 하나도 거부하지 않았다. 대신 잘못된 전사의 절반 이상을 놓쳤다.
- 놓친 것의 상당수는 **한국어가 아닌 전사**다. "Hola."(0.994), "嗯"(0.815), "kňan"(0.619), "平壤"(0.596). 신뢰도가 높아도 `language=ko`인데 한글이 없다. 이것을 저신뢰로 처리하면 0.40에서 13/17을 걸러 내고, 맞는 전사는 거부하지 않는다.
- 남은 4건은 "음"(← "응."), "그러니까?"·"이런가?"(← "그런가?")였다. 뜻이 가깝다. 짧은 동의 발화는 원인 판단이 어차피 `AGREEMENT_ONLY`·`HELP_NEEDED`로 다룬다.

권장: **0.40을 유지한다.** `RoleplaySpeechTurnPipeline`의 저신뢰 판정에 "전사에 한글이 하나도 없으면 `LOW_CONFIDENCE`"를 더한다. 0.60으로 올리면 이 표본에서는 4건을 더 거르지만, 합성 음성이라 근거가 약하다. 실제 아동 녹음(특히 1–2음절 대답)으로 다시 재서 정한다.

합성 음성은 실제 아동 녹음보다 또렷하다. 위 값은 상한으로 읽는다.

## 다음 측정

1. Elice MLAPI 경로가 열린 환경(로컬 PC 또는 운영 서버)에서 Haiku 4.5, Gemini 3.1 Flash Lite, gpt-5.4-mini를 같은 조건으로 3회씩 잰다. 판단 프롬프트 수정이 들어간 뒤에 잰다.
2. 타입캐스트 계정 문제를 해결하고 음성 왕복(`--speech`)을 다시 잰다. `TTS_TIMEOUT`을 확정한다.
3. 아동 녹음 표본을 모아 STT 신뢰도 기준을 다시 본다.
4. 운영 서버(서울)에서 한 번 더 재서 `AI_TIMEOUT`을 확정한다.

## 재현 방법

```bash
cd backend
export AI_BASE_URL=https://api.openai.com/v1 AI_API_KEY=... AI_TIMEOUT=30s
for m in gpt-5.4-nano gpt-5.4-mini gpt-4.1-mini; do
  AI_MODEL=$m ./gradlew roleplayEval --args="--provider openai --repeats 3 --run-id $m-r3"
done
./gradlew roleplayEval --args="--compare build/eval/gpt-5.4-nano-r3,build/eval/gpt-5.4-mini-r3,build/eval/gpt-4.1-mini-r3"

export STT_API_KEY=... TTS_API_KEY=... TTS_VOICE_ID=...
./gradlew roleplayEval --args="--skip-llm --speech --repeats 3 --run-id speech-r3"
```

측정하면서 겪은 것:

- 클라우드 세션에서는 Maven Central이 429(요청 과다)를 돌려줬다. 임시 Gradle init 스크립트로 Google의 Maven Central 미러를 썼다. 저장소 설정은 바꾸지 않았다.
- `--note`에 한글을 넣으면 `summary.md`의 메모가 `???`로 깨졌다. 실행 환경 로캘이 UTF-8이 아니어서 JVM이 인자를 잘못 읽은 것으로 보인다. `LANG=C.UTF-8`로 실행하거나 메모를 영어로 쓴다.
- OpenAI TTS로 한 STT 측정은 `roleplayEval`이 아니라 따로 만든 스크립트로 했다. STT 호출 파라미터와 신뢰도 계산은 `OpenAiSpeechToTextProvider`와 같게 맞췄다.
