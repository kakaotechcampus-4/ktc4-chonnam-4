## 문제와 변경 결과

역할극 검수 출력에서 허용되지 않은 실패 코드·분석 근거 혼동·판정과 사유의 모순 때문에
연결 성공 후에도 출력이 거절되거나 정상 후보 확보에 실패했다.
검수 요청의 분석·관찰 범위를 서버가 고정하고, 현재 관찰 상태에 맞는 허용 조합을
네이티브 JSON schema로 전달한다. 수신 후에는 실제 인용 출처·참조·판정 정합성을 계속 검사한다.
실패한 출력을 임의로 PASS로 고치거나 기본 근거로 채우지 않는다.

## 변경

- 평가 wire schema v5 / 프롬프트 v7. 분석·후보 검수를 구분하고 서버가 승인 여부·실패 코드·재시도 대상을 계산한다.
- 구조 오류와 판단보류를 구분하고 서버가 확인한 수정 조건을 기존 재시도 경로에 전달한다.
  기존 반복 상한·공유 60초 예산·제공자/SDK 재시도 0 정책은 유지한다.
- `.env.local`의 실제 모델·추론 설정으로 평가 실행기를 실행하고 모델별 고유 결과 폴더에 저장한다.
  과거 진단은 테스트 전용으로 유지하며 별도 Spring AI Advisor 반복이나 프레임워크 업그레이드는 추가하지 않는다.
- 선택적 호출 로그에 요청 식별자·프롬프트/스키마 버전을 연결하고 제공자 성공·서버 검증·최종 HTTP 결과를 구분한다.
- ROLEPLAY_STAGE/ROLEPLAY_TIMING으로 큐 대기·문맥·입력 처리·AI 호출·검증·STT/TTS·저장 시간을 연결한다.
  worker에 관측 문맥을 명시적으로 넘기고 포함/자체 시간·응답 시 미완료·늦은 종료를 구분한다.
  원문 진단을 끈 상태에서도 호출 로그 설정으로 시간 관측이 가능하다.
- dev 한정 진단 파일에 실제 모델 메시지·가공 전 출력·검증 결과를 같은 UUID로 기록한다.
  기본 비활성, 기본 15분/10요청/총 20MiB/사건 1MiB이며 콘솔·공개 API와 분리한다.
  저장 실패가 사용자 처리 결과를 바꾸지 않으며 DEBUG 로그에도 예외 원문을 출력하지 않는다.
- Parameter Store 전달 목록과 실제 서버 관측 실행 절차를 추가한다.

## 검증

- 공식 develop `d6f7e06` 반영 및 구간별 시간 관측 추가 후 `./gradlew --no-daemon spotlessApply build` 성공(2분 57초).
  총 2,865개 중 2,859개 통과, 선택 실행 항목 6개 제외, 실패 0개.
- 관찰 상태/판정/사유/인용 조합과 실제 인용 출처, 재시도·예산·HTTP 저장 경로 회귀 검사를 포함한다.
- 원문 파일 권한·동시 요청 격리·수집 한도·저장 실패·원문 로그 비노출·HTTP trace 연결을 가짜 provider로 검증했다.
- 가짜 시계/제어된 worker로 큐·구간 겹침·반복 호출·거절/취소/timeout·늦은 종료·요청 격리·기록 실패를 검증했다.
  HTTP에서 입력 판정 및 STT/AI/TTS/저장 시간 연결, 멱등 재전달의 AI 0회를 확인했다.
- 최종 검사에서 발견한 DEBUG 예외 메시지 노출을 수정하고 DEBUG를 강제한 회귀 검사로 확인했다.
- Linux 환경에서 마이그레이션 가드와 서버 배포 자체 검사 통과.
- 앞선 실제 `gpt-6-luna/low` 고정 반례 2건은 잘못된 분석→REANALYZE, 잘못된 후보→REGENERATE로 각각 유효하게 거절했다.
  이는 동기화 전 `9ffa124` 기반 작업본에서 수행한 평가 호출이며, 재분석·재생성·저장까지 실행한 실제 서버 검증은 아니다.
  이번 원문 수집 검증에는 추가 실제 AI 호출을 하지 않았다.

## 배포 후 확인

[Dev 서버 관측 실행 절차](roleplay-dev-observation-runbook-2026-11-08.md)에 따라
설정 적용 → 배포 SHA 확인 → 팀 테스트 계정의 실제 텍스트 입력 → Network의 X-Trace-Id → 원문 파일/로그 → 저장 재조회 순서로 확인한다.
push 대상은 공식 저장소(upstream)의 `refactor/evaluation-output-retry`이며 같은 저장소의 `develop`을 대상으로 PR을 준비한다.
refactor 브랜치 push만으로 팀 AWS develop 서버에 배포되지 않는다. 팀 develop CI·리뷰·머지·배포 결과를 확인해야 한다.

로컬 `.env.local`은 서버에 복사하지 않는다. 실제 서버 모델·low·timeout·재시도·호출 로그 설정은 Parameter Store에서 확인한다.
`.env.local`·점 없는 `env.local`·build/eval 결과는 Git 추적에서 제외한다. 실행기와 테스트 소스만 공유한다.
원문 진단은 dev 프로필과 호출 로그 활성화가 필요하다. 종료 후 설정을 끄고 배포에 반영하며 진단 파일을 정리한다.
15분 만료는 수집 중지이며 파일 자동 삭제가 아니다.

## 한계와 후속 작업

고정 사례의 성공을 전체 품질·성능 개선으로 일반화하지 않는다.
실제 AWS 입력·저장·음성 관측은 아직 수행하지 않았다. 개별 SQL·외부 AI 내부 추론 시간과 부하 지표 대시보드는 이번 범위에 포함하지 않았다.
스키마 통과 후에도 의미 판단 오류가 남을 수 있으므로 실제 문맥과 출력은 사람이 함께 검토한다.

직접 수정한 프론트엔드 파일은 없다. 개발자 도구에서 trace ID를 확인할 수 있다.
화면 내 진단 ID 표시가 필요하면 프론트엔드 후속 과제로 진행한다.
