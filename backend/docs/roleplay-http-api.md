최초 기록 기준: develop `c644dc2`, `feat/roleplay-response-pipeline`.
현재 통합 기준: PR #80 `c306bd1`과 develop `565beb6`의 충돌 해결 작업본, 2026-10-28.

## 완료·보상과 학습 결과를 읽는 기준

활동 완료·보상, 목표 달성 판정 및 후속 난이도는 [완료·보상 연동 계약](roleplay-completion-integration.md)의 현재 적용 기준을 따른다.
목표 달성 또는 서버가 확인한 최대 턴 종료에 의한 정상 마무리는 활동 완료·스탬프 지급 대상이지만,
최대 턴으로 완료됐다는 사실을 목표 달성이나 난이도 상향으로 바꾸지 않는다. 후속 난이도는 기존 목표별 근거의 유지·하향·상향 후보 규칙을 보존한다.
현재 코드는 목표 달성에 의한 완료를 연결했고, 최대 턴 종료의 완료·보상 연결과 후속 난이도 계산·적용은 아직 남아 있다.

음성 응답의 HTTP 200만으로 학습 턴 저장 성공을 판단하지 않는다. `DELIVERED`는 DB에 확정된 응답 또는 그 재전송을 뜻하며,
활동 전체의 완료·목표 달성을 자동으로 뜻하지 않는다.
프론트엔드의 활동 완료·스탬프 표시는 서버의 활동 status 조회 결과를 따른다. 이번 문서 정리로 공개 응답 필드를 추가하지 않는다.
아래 테스트 수치는 각 기준 커밋에서 실행한 과거 기록이다. 이번 통합 작업본의 신규 테스트 결과로 재사용하지 않는다.

## 구현 흐름

기존 아동 입장 API → 서버 세션 + CSRF → 음성 입력 컨트롤러 → 인증된 아동의 세션/활동 조회
→ 업로드 검증/임시 파일 → 서버 SHA-256 지문 → 처리권/기존 결과 확인 → 승인 입력 조립
→ STT/표준화·안전 처리/분석·생성·평가/TTS → 서버의 활동 목표 판정
→ 짧은 턴/완료 저장 트랜잭션 → 공개 응답.
외부 호출 동안 DB 트랜잭션을 유지하지 않는다. 확정 이전 후보는 성공 응답으로 내보내지 않는다.
승인 입력의 학습 증거 참조·이전 확정 관찰은 음성 파이프라인을 거쳐 분석/검수에 필수 전달한다.
표준화는 이번 발화만 교체하고 이 관찰 자료를 재작성하지 않는다. 분석/검수는 v2 단일 계약이며 v1로 우회하지 않는다.
새 턴 저장 직전에는 활동→아동→세션 순서로 행을 잠그고 참여 상태·활동 진행 상태·시나리오를 재검사한다.
삭제·퀴즈와 함께 사용하는 [DB 잠금 순서 규칙](database-locking.md)을 따른다.
다른 종료/상태 변경 작업이 같은 부모/세션을 잠그면 이 잠금 순서를 맞춰야 한다. 기존 결과 재전송은 새 턴을 만들지 않는다.

## 요청

`POST /api/v1/roleplay-sessions/{sessionId}/voice-inputs`

- 아동 서버 세션 쿠키와 CSRF 헤더가 필요하다. 강사 Bearer 인증으로는 입력을 제출할 수 없다.
- `GET /api/v1/csrf` 응답의 headerName/token을 사용한다. 기존 아동 입장 API도 CSRF가 필요하다.
- `Idempotency-Key`: UUID, 필수. 네트워크 재전송은 원래 키와 원래 음성 바이트를 유지한다.
- `Content-Type`: multipart/form-data. 브라우저 FormData의 boundary를 수동 설정하지 않는다.
- `audio`: 필수 파일 파트. filename은 저장 경로에 쓰지 않는다.
- 아동 ID, 활동 ID, 후보 ID, 지문을 요청에서 받지 않는다. 활동은 본인 세션에서 조회한다.
- clientInputId/recordedDurationMs는 이번 API 계약에 추가하지 않았다. 실제 길이/디코딩 검증은 미구현이다.
- 선언 MIME은 AudioFormat으로 정규화한 뒤 주입된 허용 목록과 대조한다. 실제 컨테이너/코덱 판별을 의미하지 않는다.

## 응답

기존 `ApiResponse`/`ApiErrorResponse` 및 `X-Trace-Id`를 재사용한다.
완료/복구 응답은 Cache-Control: no-store. 정상 처리 결과는 200이며 비동기 작업 접수 API가 아니다.

| HTTP | 응답 | 의미 |
|---|---|---|
| 200 | data.status=DELIVERED | DB에 확정된 응답 또는 동일 입력 재전송 |
| 200 | REINPUT_REQUIRED / RETRY_REQUIRED / STOPPED / NOTICE_UNAVAILABLE | 승인 안내와 행동 또는 미확정 안내 부재. 학습 턴 저장 성공과 구분 |
| 202 | PROCESSING, action=WAIT | 같은 세션·키·입력의 요청이 이미 실행 중. 완료 판정 아님 |
| 400 | 공통 요청 오류 / VOICE_UPLOAD_EMPTY | UUID·필수 헤더/파트 형식 오류 또는 빈 파일 |
| 401 | AUTHENTICATION_REQUIRED | 아동 입장 필요 |
| 403 | ACCESS_DENIED / CSRF_TOKEN_INVALID | 아동 권한 또는 CSRF 실패 |
| 404 | ROLEPLAY_NOT_FOUND | 본인 세션/활동이 없거나 아동이 비활성 |
| 409 | ROLEPLAY_CONFLICT | 같은 키의 다른 입력 또는 체크포인트 충돌. 원인을 단정하지 않음 |
| 413 | VOICE_UPLOAD_TOO_LARGE 또는 서블릿 공통 오류 | 실측 업로드/전체 multipart 크기 초과 |
| 415 | VOICE_UPLOAD_FORMAT 또는 공통 Content-Type 오류 | 허용되지 않은 선언 MIME/요청 형식 |
| 503 | ROLEPLAY_CONTEXT_UNAVAILABLE | 승인 콘텐츠/진행 상태가 없거나 일치하지 않음, 또는 활동 목표를 판정할 수 없음 |
| 503 | ROLEPLAY_BUSY | 처리 용량 부족. 재시도는 같은 요청 키·입력으로 판단 |
| 500 | INTERNAL_ERROR | 저장/IO/예상하지 못한 제공자·발행 장애. 내부 원문 비노출 |

200/202 data 필드는 status, action, messages(text, speech.available/url), acceptedInput,
checkpointVersion, replayed이다. 신규 정상 응답에는 검증된 표준 발화 acceptedInput이 있으며,
재전송/실패에서는 null이다. 재전송은 저장된 문구를 반환하고 음성을 다시 생성/발행하지 않는다.
평가·실패 후보·원본/STT·제공자 정보·강사용 위험 안내·승인 메타데이터는 공개 응답에 넣지 않는다.
202 결과 조회 경로/자동 재시도 주기/Retry-After는 구현하거나 임의 확정하지 않았다.

## 처리권과 운영 전제

현재 처리권은 `InMemoryRoleplayRequestGuard` 단일 Spring 빈이 관리한다.
동일 `(sessionId, Idempotency-Key)`를 원자적으로 확보하며, 실제 작업자 종료 시 해제한다.
처리권에는 서버가 계산한 입력 지문만 메모리에 함께 보관한다. 같은 키로 처리 중인 입력과
지문이 같으면 202 PROCESSING, 다르면 409 ROLEPLAY_CONFLICT를 반환하고 추가 AI 호출을 하지 않는다.
처리권 해제 시 메모리 항목도 제거하며, 확정 이후에는 기존 DB 지문으로 재전송을 검사한다.
AI 호출 대기 중 처리권 때문에 DB 연결을 점유하지 않는다. 처리량은 기존 작업자·대기열로 제한한다.
확정 결과 조회·저장은 계속 DB를 사용하며, 입력 지문 검사와 체크포인트 충돌 검사는 유지한다.

백엔드 한 개를 실행하는 운영 전제다. 여러 인스턴스나 배포 중 구·신 서버 동시 실행에서는
메모리 처리권을 공유하지 못하므로, 확장 전에 공유 처리권 구현과 장애 시 소유권 정책이 필요하다.
프로세스가 저장 전 종료되면 같은 요청의 외부 AI 호출이 다시 실행될 수 있다.
정상 종료에는 최대 60초 턴보다 긴 Spring 대기 70초와 backend 컨테이너 종료 유예 90초를 적용한다.
단일 서버 운영 조건, 배포·강제 종료의 한계와 재시작 후 재전송은
[종료·재전송 계약](roleplay-single-backend-lifecycle.md)을 따른다. 다중 서버 공유 처리권을 추가한 것은 아니다.

## 활성화와 필수 연결

`roleplay.http.enabled=true`일 때만 컨트롤러와 실행 설정을 등록한다. 기본은 비활성이다.
활성화한 상태에서 필수 정책이나 구현이 없으면 Spring 시작 단계에서 실패한다.
테스트용 구현을 운영 기본값으로 등록하지 않는다.
배포 환경변수와 Parameter Store 경로는 [역할극 운영 설정 전달](roleplay-runtime-config.md)을 따른다.
활성화 시 `roleplay.progress.maximum-turn-count`와 `maximum-support-turns-per-micro-goal`을 모두 양수로 공급해야 한다.

필수 설정:

- spool-directory: 서버가 관리하는 기존 임시 디렉터리. 클라이언트 경로를 쓰지 않는다.
- maximum-upload-bytes: 음성 파일 크기. 기존 SpeechTranscriptionRequest의 2MB 처리 용량 이하로 명시해야 한다.
- maximum-request-bytes: multipart 전체 크기. 파트 헤더/boundary 등의 추가 크기까지 포함해 설정해야 한다.
- allowed-formats: AudioFormat 허용 목록. WEBM/OGG/WAV/MP3/MP4 중 확정 정책에 맞춰 명시한다.
- worker-count/queue-capacity: 운영 처리 자원 수와 대기 용량. 대기 용량 0도 지원한다.
- turn-budget: 선택. 기본 최대 60초, 양수이며 60초 이하만 허용한다. 짧은 예산은 장애 재현 테스트에도 사용한다.
- notices: 승인된 kind/text/version/approval-reference 목록. 없으면 TIMEOUT 확정 문구만 제공하고 그 외는 NOTICE_UNAVAILABLE로 처리한다. TIMEOUT 재정의는 허용하지 않는다.

필수 제공자와 현재 연결 상태:

1. RoleplayContextSource: DB 조회 구현 `JdbcRoleplayContextSource`를 추가했다. 시나리오 PR의 V15 자료와 V16 관찰 이력, 명시적인 `RoleplayProgressSource`가 필요하다. 목표별 확정 응답 이력에서 질문 횟수·정답 제공 여부를 복원한다. 현재 목표·지원·제한 등 나머지 진행 공급자가 없으면 기본값을 만들지 않고 컨텍스트 불가로 처리한다.
2. RoleplayInputProcessor: 실제 의미 보존 표준화, PII 제거 및 위험 입력 판정.
3. SpeechToTextProvider/TextToSpeechProvider: 담당 PR의 실제 어댑터/설정과 연결. 포트만 테스트용 구현으로 검증했다.
4. RoleplaySpeechDelivery: 인증된 수신자가 접근할 수 있는 임시 음성 주소. 보관 기간/전달 정책과 실제 구현은 미정이다.
5. RoleplayActivityGoalEvaluator: `ServerRoleplayActivityGoalEvaluator`가 검수된 분석과 다시 조회한 서버 자료로 `RoleplayGoalObservationPlan`을 준비한다. 분석 당시 자료의 지문과 재조회 자료가 같아야 한다. 자료 변경·관찰 근거 불일치·판정 불가는 기존 503이며 저장하지 않는다. 추가 AI 호출이나 임의 달성 기본값은 없다.

음성 HTTP의 저장 경로는 `RoleplayCompletionCheckpointStore`를 사용한다.
이미 확정된 요청은 DB 결과 조회에서 끝나므로 AI·목표 판정을 다시 호출하지 않는다.
새 승인 응답의 관찰·판정 변경안은 저장 트랜잭션 밖에서 같은 60초 이내 예산으로 준비한다.
새 턴 저장 시 판정·관찰·근거 참조도 같은 트랜잭션에 반영한다. 관찰 또는 완료 저장이 실패하면 턴과 진행 상태도 취소한다.
달성이면 턴·관찰·완료·지급 시각·실제 학습 기록·발화 삭제를 함께 확정하고, 미달성이면 턴·관찰·판정을 저장한다.
판정 불가 또는 잘못된 빈 판정값은 기존 `503 ROLEPLAY_CONTEXT_UNAVAILABLE`로 처리하며 후보 전달·저장을 하지 않는다.
클라이언트의 `achieved`/`isFinished` 값은 이 판정에 사용하지 않는다. 공개 응답 필드와 요청 본문은 추가하지 않았다.

활동 완료 확인은 PR #76의 `GET /api/v1/activities/{activityId}/status`로 한다.
읽기는 완료·보상을 다시 실행하지 않으며 아동의 쿠키 인증·소유권 검사가 적용된다.
판정 공급자는 실제 목표 관찰 결과를 읽어야 하며 CLOSING·검수 PASS만으로 달성이라고 판단하면 안 된다.

LlmProvider는 기존 BE 제공자 빈을 주입받는다. 실제 제공자 호출/보관 계약·키 설정을 이번 검증에서 사용하지 않았다.
연결된 제공자는 호출당 1회 시도를 수행해야 전체 재시도 예산을 지킬 수 있다.
역할극 HTTP 활성화 시 LLM의 SDK 내부 재시도가 0회인지 설정과 실제 ChatModel 옵션을 검사한다.
`callBudget`이 전달된 호출에서도 같은 조건을 검사하며, 재시도 설정이 0회가 아니면 호출하지 않는다.
STT/TTS 어댑터에는 내부 재시도가 없다. 다른 제공자를 연결할 때도 같은 계약을 지켜야 한다.
서버 세션 생성/승인 시나리오 준비 API는 기존 담당 영역의 선행 작업이며 이 음성 입력 API가 만들지 않는다.

## 시간 제한과 삭제 범위

컨트롤러 진입 후 하나의 예산을 인증 조회·spool·대기·STT·LLM 재시도·TTS·체크포인트에 공유한다.
서블릿 multipart 파싱은 컨트롤러 진입 전이며 별도의 서버 크기 제한을 적용한다. 차단된 DB/입력 IO의 물리적
취소, 네트워크 업로드 시간, COMMIT/음성 발행 경계에 대한 제품 계약은 최종 확정이 필요하다.
실행 중 늦은 제공자 응답은 다음 단계나 DB 저장으로 진행할 수 없다. 물리적으로 멈추지 않는 작업은
작업이 종료될 때까지 처리권을 보유한다. 큐 포화는 503이며 무제한 대기를 만들지 않는다.
STT·LLM·TTS는 [호출별 예산](roleplay-call-budget.md)을 전달받아 설정 상한과 남은 턴 시간 중 작은 값을
실제 요청 제한에 적용한다. 이 변경은 60초 턴 기본값이나 CloudFront 설정을 변경하지 않는다.
임시 업로드는 실패/충돌/재전송/시간 초과/정상 반환에서 삭제한다. 서블릿 multipart 임시 데이터는 서블릿이
요청 종료 때 정리한다. DEC-008 별도 보관본 및 세션 종료 삭제 트리거를 대신 구현한 것은 아니다.

음성 실패 누적 범위/초기화, 원본/STT/실패 후보의 DEC-008 보관 수명주기,

기존 구현 전체 검증(이번 변경 전): `./gradlew --offline test spotlessCheck` — 전체 754개, 실패 0, 오류 0, 건너뜀 0.

외부 제공자의 정확히 한 번 실행을 검증한 것은 아니다. 운영 코드는 이 단계에서 변경하지 않았다.


## 확정 응답의 진행 복원용 기록 — 2026-10-28

V17은 확정 턴의 응답 종류·사용 전략을 기존 턴 저장 트랜잭션에 함께 기록한다.
클라이언트가 이 값을 보내거나 직접 지원 수준을 판정하는 계약은 추가하지 않았다.
이미 확정한 요청을 재전송하면 처음 저장한 종류·전략을 유지하고, 표준 발화 삭제 뒤에도 기록을 유지한다.
과거 종류·전략을 알 수 없는 턴은 NULL로 두며 질문 또는 정답 미제공으로 간주하지 않는다.
지원 규칙의 조건은 통합 워크플로우 14절과 LVL-13~18에 있다. 수치 충돌과 진행 공급 구현의 잔여 범위는 완료 연동 문서를 따른다.


## 확정 응답 이력 기반 컨텍스트 — 2026-10-28

현재 질문 목표의 질문 횟수·정답 제공 여부는 DB에 확정한 응답 종류로 구성한다.
관찰 목표의 달성 여부와 다음 질문 목표를 합치지 않는다. 지원 노출 기록만으로 독립 도달을 판정하지 않는다.
과거 종류/전략 누락, 이력과 체크포인트 불일치, 승인 범위 밖 목표는 기존 ROLEPLAY_CONTEXT_UNAVAILABLE다.
이미 확정한 같은 요청은 기존 DB 재조회로 복원하므로 새 분석용 컨텍스트가 없어도 재전송할 수 있다.
공개 요청/응답 필드와 오류 코드는 바뀌지 않았다. 운영 진행 정책 공급·실제 제공자·브라우저 연동은 남아 있다.


## 입력 당시 목표·지원의 내부 저장 — 2026-10-28

입력 당시 상태는 서버 Prepared 자료에서 전달하고 V18로 확정 턴에 보존한다.
클라이언트가 inputMicroGoalId/inputSupportLevel/inputSupportTurn/inputPromptCount/inputAnswerRevealed를 보내는 계약은 없다.
요청 값으로 서버 상태를 덮어쓰지 않으며 공개 응답에 내부 입력 상태를 추가하지 않았다.
자료 지문이 같아도 입력 상태가 다르거나 누락되면 기존 ROLEPLAY_CONTEXT_UNAVAILABLE다.
과거 입력 상태는 미확인으로 유지하고 새 분석의 응답 종류 검증 및 확정 결과 재전송 계약은 그대로다.


## 입력 횟수·유도 턴의 확정 이력 복원 — 2026-10-28

현재 질문 목표의 다음 유도 턴은 해당 목표에 확정한 입력 수+1이다. 정책 제공자/클라이언트의 별도 번호를 받지 않는다.
관찰된 목표나 다음 질문 횟수를 입력 시도 횟수로 대체하지 않는다. 이 값으로 완료·지원 조정을 자동 판단하지 않는다.
입력 당시 목표가 누락된 과거 턴이 있으면 정확한 번호를 만들 수 없어 새 분석은 기존 ROLEPLAY_CONTEXT_UNAVAILABLE다.
확정 결과의 같은 키 재전송은 계속 가능하며 공개 요청/응답 필드·오류 코드는 추가하지 않았다.
운영 진행 정책 공급·실제 모델/음성·브라우저 및 최종 마이그레이션 이력 검증은 남아 있다.


## 확정 관찰의 사전 지원 연결 — 2026-10-28

과거 관찰은 같은 확정 입력 당시 상태와, 그 목표에 발화 전에 제공한 응답 이력에 연결한다.
같은 턴/나중 턴의 정답 제공을 과거 발화의 사전 도움으로 사용하지 않는다.
이 정보는 서버의 분석·검수용 내부 입력이며 요청/응답에 필드를 추가하지 않는다.
연결 자료가 불완전하면 기존 ROLEPLAY_CONTEXT_UNAVAILABLE이며 확정 결과 재전송 경로는 유지한다.
이 기록만으로 독립 도달·활동 완료를 자동 판정하지 않는다.


## 현재 발화의 목표별 사전 지원 — 2026-10-28

서버가 모든 승인 목표의 확정 지원 이력을 기존 분석·검수에 공급한다.
클라이언트가 목표별 질문 수나 정답 제공 여부를 보내는 필드는 추가하지 않았다.
현재 발화/미래 턴의 응답을 사전 지원으로 받지 않으며 자료 부족은 기존 컨텍스트 불가 경로다.
공개 요청·응답·오류 코드 및 확정 결과의 같은 키 재전송 계약은 유지한다.


## 지원 제안의 확정 이력 대조 — 2026-10-28

정답 제공 목표의 추가 학습 유도와 같은 목표의 지원을 낮춘 반복 유도는 분석 단계에서 거절한다.
기존 분석 재시도/복구 예산을 사용하며 검수 후 저장 직전에도 실제 서버가 같은 조건을 확인한다.
저장 직전 충돌은 기존 ROLEPLAY_CONTEXT_UNAVAILABLE이고 새 목표/지원·관찰·완료/보상을 확정하지 않는다.
공개 필드·오류 코드를 추가하지 않았으며 이미 확정된 결과의 같은 키 재전송 계약도 유지한다.
