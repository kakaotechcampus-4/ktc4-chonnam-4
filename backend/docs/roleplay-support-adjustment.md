# 지원 판정 이력과 연속 달성 정책

브랜치 `feat/roleplay-support-adjustment`의 기준은 develop `ccfdff0`이다. 입력 복구 브랜치에 의존하지 않으며 프론트엔드는 수정하지 않는다.

## 확정 정책

사용자 확정에 따라 서로 다른 작은 목표 2개를 힌트 없이 연속 달성하면 다음 목표의 지원 감소 자격을 얻는다. 부분 이해·도움 요청은 연속성을 초기화한다. 판정 불가 입력은 독립 달성을 더하지 않고 기존 연속성을 유지한다. 정책 버전은 `SUPPORT_DECREASE_V1`이며 이 버전으로 기준 수나 초기화 규칙을 바꾸면 시작 시 거절한다.

힌트 없는 도달은 현재 목표의 승인된 필수 학습 증거가 이번 발화의 긍정 관찰에 모두 존재하고, 사전 도움·정답 제공 이력이 이를 뒷받침할 때만 인정한다. 다른 목표의 질문 지원을 복사하지 않으며 이력이 없는 과거 판정을 독립 달성으로 추정하지 않는다. 정답을 이미 제공한 목표의 응답은 독립 도달과 구분한다.

## 이번 커밋의 실행 경로

검수된 턴 → 서버의 입력 목표·관찰·사전 도움 대조 → 입력 목표 도달 방식/지원 결정과 관찰 근거 저장 → 다음 승인 문맥 조회 시 시간순 확정 이력 복원 → 정책 자격 계산 순서로 동작한다. 판정과 근거는 기존 턴·관찰과 같은 트랜잭션으로 저장하며 저장 실패 시 함께 롤백된다. 같은 요청 재전송은 기존 결과를 복원한다. 아동 삭제는 새 근거 테이블도 같은 삭제 트랜잭션에서 정리한다.

새 V30은 `roleplay_goal_assessment`의 `input_goal_outcome`·`support_decision`과 `roleplay_input_goal_basis`를 추가한다. 기존 V1~V24는 변경하지 않으며 원래 미커밋 검증본의 V26을 V30으로 옮겼다. 과거 행의 새 판정 값은 채우지 않는다. 표준 발화 삭제 후에도 검수된 학습 판정·근거는 유지해 이력을 복원한다.

원본 develop의 최대 턴 완료·보상 처리와 활동 목표 달성의 긍정 근거 검사를 유지하면서, 상한 판단은 확인된 학습 입력 순번에 맞췄다. 생성 전 지원 수준 보정과 저장 전 보정 재검증을 연결했다. 한 단계 상승 제한과 판정 불가 입력의 학습 유도 횟수 제외도 연결했다.

## 설정과 검증

애플리케이션의 기본 설정은 목표 2개·`RESET_SEQUENCE`·`SUPPORT_DECREASE_V1`이다. 세 설정을 함께 명시해야 하며 기획 변경 시 정책 버전을 함께 변경해야 한다. 설정 없는 독립 실행에서는 임의 값을 추정하지 않고 `POLICY_REQUIRED`를 반환한다.

정책·판정·관찰 이력·승인 문맥·저장 계획·최대 턴 관련 검사와 HTTP·완료·아동 삭제 회귀 검사, `spotlessCheck` 및 마이그레이션 가드가 통과했다. 실제 PostgreSQL에서 판정/근거 저장·복원·중복 요청·롤백·삭제를 확인했다. 전체 브랜치 빌드 결과는 아래에 정리했다. 실제 외부 모델·브라우저를 통한 종단 검증은 포함하지 않는다.

## 다음 목표의 실제 지원 감소

두 번째 목표를 힌트 없이 달성한 입력까지 포함해 정책 자격을 계산한다. 아직 질문하지 않은 새 목표의 시작 수준을 모델이 S2로 제안하면 서버가 S1로 보정한 분석을 생성·검수에 전달한다. S0는 유지하며 `AT_MINIMUM`으로 기록한다. 같은 목표나 이미 질문한 목표에는 소급해 적용하지 않는다. 목표를 바꾸는 제어 전략으로 시작 질문 규칙을 우회할 수 없다.

모델 응답에서 서버 적용 결과를 받지 않고, 원래 제안과 확정 판정 이력으로 서버가 계산한다. 검수 거절 후 재분석은 새 원래 제안에서 다시 계산하므로 S2→S1→S0처럼 중복 차감하지 않는다. 저장 전에는 원래 제안·현재 근거로 보정 결과를 재계산해 적용 정보 삭제·수준 변경·정책 버전 위조를 거절한다.

V31은 원래 제안/적용 수준·목표·정책과 도달 근거를 턴/판정과 같은 트랜잭션에 저장한다. 적용 기록과 실제 저장 턴의 목표·수준, 근거 관찰을 FK·제약으로 연결하고 불완전한 저장은 롤백한다. 동일 요청 재전송은 저장 결과를 복원하며 지원을 다시 낮추지 않는다. 아동 삭제 시 적용 기록과 근거도 삭제한다. 원래 미커밋 검증본의 V27을 V31로 이관했으며 기존 V30은 변경하지 않았다.

프론트엔드의 API 요청·응답 형식에는 이번 보정으로 추가되는 변경이 없다. 기존 역할극 응답을 그대로 표시한다. 실제 모델과 화면을 통한 질문 내용·지원 수준 검증은 남아 있다.

이번 지원 감소 연결은 생성/검수 프롬프트·재분석·서버 재검사 관련 검사와 실제 PostgreSQL 저장·복원·위조 거절·롤백·삭제 검사가 통과했다. HTTP·완료·삭제·문맥 조회 회귀 194개 검사, 포맷 검사와 마이그레이션 가드도 통과했다. 최신 develop의 최대 턴 종료와 긍정 관찰 근거 검사도 유지·검증했다.

## 지원 상승과 학습 유도 횟수

같은 목표의 지원은 한 번에 한 단계만 높인다. 유도 횟수 상한에 도달해도 S0→S2/S3, S1→S3처럼 중간 단계를 건너뛰지 않는다. 판정 불가는 질문 목표·지원 수준을 바꾸는 근거가 아니다. 모델 분석 검사와 저장 직전 재검사에 같은 규칙을 적용한다.

저장 입력 순번인 `turn_count`·`current_micro_goal_support_turn`은 그대로 유지한다. `learning_turn_count`·`current_micro_goal_learning_support_turn`을 별도로 복원하고 `NOT_ASSESSABLE`을 제외한다. 기술적 입력 실패는 학습 턴을 저장하지 않으므로 학습 횟수도 늘리지 않는다. 학습 순번과 사전 도움 정보는 분석·검수에 같은 값으로 전달한다.

전체 상한에서는 평가 가능한 현재 입력까지 포함한 학습 순번으로 마무리하고, 현재 목표·지원 수준을 유지한다. 완료 저장 트랜잭션 안에서도 이전 판정 이력을 확인하므로 생성 프롬프트만 바꾸고 저장 시 조기 완료되는 일이 없게 했다. 판정 불가 자체로 상한 완료·보상을 만들지 않는다. 활동 목표 달성에 의한 완료는 별도로 유지한다.

이력이 누락되거나 과거 판정을 확인할 수 없으면 학습 순번을 null로 두고 학습 횟수를 추정해 상한을 적용하지 않는다. 입력 목표 판정 계약이 없는 이전 내부 호출 경로에는 기존 저장 순번 상한을 유지한다. 원래 최대 턴 완료의 재전송·경합·저장 실패 롤백·보상 중복 방지 동작은 유지한다.

실제 DB 검사에서 판정 불가→정상→판정 불가→정상 입력의 저장 순번은 4, 학습 순번은 2였으며 상한에서 완료·보상이 한 번만 확정됐다. 재전송과 표준 발화 삭제 후에도 학습 횟수가 복원됐다. 지원 상승·판정 불가·전체 상한의 생성/검수 검사와 기존 최대 턴 완료 검사가 통과했다. 새 마이그레이션은 필요하지 않다. 전체 브랜치 회귀 빌드와 PR 초안 정리를 마쳤다.
