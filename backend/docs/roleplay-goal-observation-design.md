# 목표 관찰과 활동 목표 판정의 공급 설계

2026-10-28. S3-JIN-02 완료 연결의 선행 공급인 S6-JIN-01 목표 관찰 범위.
코드 기준은 PR #76 head `92bb7fd`와 현재 연동 브랜치다. 아래 이름과 필드는 내부 설계이며 새 공개 API 계약이 아니다.

## 적용 기준

각 역할극의 활동 목표가 달성되면 정상 완료·스탬프 1회를 확정한다는 사용자 확인을 적용한다.
작은 목표 목록의 순차 통과나 ‘모든 항목 달성’을 별도 완료 조건으로 추가하지 않는다.
정답 제공은 스스로 도달한 결과와 구분하고, 기술 실패·위험 입력은 관찰 성취로 반영하지 않는다.
최대 턴 수와 지원 변화의 미정 수치는 이번 설계에서 정하지 않는다.

## 구분할 세 가지 정보

| 구분 | 내용 | 기존 코드와의 관계 |
|---|---|---|
| 목표별 관찰 | 이번 발화에서 어느 작은 목표의 어떤 학습 증거가 관찰됐는지 | 현재 `AnalysisResult`에 배열이 없어 확장 필요 |
| 다음 질문 초점 | 다음 응답에서 어느 목표를 물을지 | 기존 `nextStrategy.targetMicroGoalId`·후보의 목표 ID를 재사용 |
| 활동 목표 판정 | 승인된 활동 목표를 달성했는지와 그 판단이 참조한 근거 | 현재 단일 `learningState`로 대신하지 않음 |

예를 들어 감정에 대한 증거를 확인하고 다음 질문을 이유로 옮겼다면, 감정의 관찰과 이유의 질문 초점을 따로 기록한다.
관찰 배열을 목표 ID로 묶고 배열 순서·번호를 선행 통과 조건으로 사용하지 않는다. 한 턴에서 여러 목표를 관찰할 수 있다.

## 분석·검수 계약 보완

판정 전용 AI 호출을 새로 만들지 않는다. 기존 원인 분석과 독립 응답 검수의 내부 출력을 함께 확장한다.
프롬프트·파서·출력 버전은 함께 변경하며 현재 v1 필드를 임의로 새 관찰 결과처럼 해석하지 않는다.

분석이 제안할 관찰 정보:

- 작은 목표 ID, 해당 승인 버전의 학습 증거 참조, 관찰 상태.
- 활동 목표 달성/진행 중/판단 불가와 그 근거가 되는 관찰 참조.
- 다음 질문 초점은 위 관찰과 별도 필드로 유지한다.

관찰 상태는 기존 워크플로우의 명시적 표현·간접 표현·미표현·오해·모순을 재사용한다.
상태를 그 자체로 고정 점수나 전체 활동 완료로 변환하지 않는다.
검수는 후보 문장뿐 아니라 관찰과 활동 목표 판정도 승인 시나리오·입력·기존 관찰 결과에 근거하는지 확인해야 한다.
후보의 PASS만 있고 목표 판정 검증이 빠진 출력은 목표 달성의 확정 근거로 사용하지 않는다.
다른 턴/시나리오의 목표 ID, 승인 기준에 없는 증거 참조, 중복된 동일 관찰 키, 존재하지 않는 근거를 참조한 달성 판정은 거절한다.

## 저장할 정보

| 저장 대상 | 주된 내용 | 중복·참조 규칙 |
|---|---|---|
| 목표별 관찰 이력 | 세션·확정 턴·목표·승인 학습 증거 참조·관찰 상태·분석/검수 계약 버전 | 같은 세션·턴·목표·증거는 1개. 기존 확정 턴과 같은 세션인지 외래 키로 연결 |
| 목표별 현재 상태 | 세션·목표별 현재 관찰 결과, 시작/현재 지원, 정답 제공 구분, 근거 턴 | 세션+목표 1개. 이번 승인 관찰을 반영한 변경안으로 갱신 |

관찰 이력은 리포트와 판정 근거를 제공하고, 현재 상태는 다음 턴/재접속의 컨텍스트를 제공한다.
매번 이력 전체를 재계산하는 방식보다 저장 정합성 관리가 필요하지만, 관찰·현재 상태·턴을 같은 트랜잭션에서 확정해 맞춘다.
이미 확정된 관찰이 이후 모순과 어떻게 상호작용할지는 검증된 판정 변경안으로 표현하며,
‘한 번 달성하면 절대로 바뀌지 않음’ 같은 상태 전이 규칙을 임의로 추가하지 않는다.

첫 구현은 아동 발화 인용이나 모델의 자유 서술 관찰 문장을 영속 필드에 넣지 않는다.
승인 기준의 참조와 상태로 보관하고, 강사 표시/리포트 문구는 그 기준과 관찰 상태를 바탕으로 구성한다.
입력 원문이 없는 구조에서도 필요한 관찰·목표·지원 근거가 남아야 한다. 위험 발화/사건 정보는 포함하지 않는다.
승인 기준의 참조는 승인 시나리오 버전에 묶어 해석하며, 그 참조 형식은 실제 승인 콘텐츠 공급과 함께 구현한다.

## 준비와 확정 분리

1. 기존 서버 컨텍스트에서 승인 목표·증거·현재 상태·저장 버전을 읽는다.
2. 기존 분석·검수를 통해 관찰과 활동 목표 판정을 준비한다. 저장은 아직 하지 않는다.
3. `RoleplayActivityGoalEvaluator`는 단일 enum만이 아니라 관찰 변경안과 판정을 담은 내부 결과를 공급하도록 보완한다.
   변경안은 세션·승인 시나리오 버전·입력 턴·후보·저장 전 버전에 연결한다.
4. `RoleplayCompletionService`의 짧은 트랜잭션에서 기존 잠금/버전·요청 키 검사를 수행한다.
5. 새 턴일 때만 턴·관찰 이력·현재 상태를 저장한다. 달성이면 실제 완료·보상·기록·발화 삭제도 함께 실행한다.
6. 최종 기한 검사 후 커밋한다. 관찰 저장이나 완료 과정이 실패하면 전부 취소한다.

재전송은 기존 확정 결과 조회에서 종료한다. 관찰 이력·도달 횟수·지원 변화·보상을 다시 반영하지 않는다.
승인되지 않은 출력이나 판정 불가는 현재의 컨텍스트 불가/재시도 계약을 따르고 성공 상태를 만들지 않는다.
목표 관찰을 먼저 별도 트랜잭션으로 저장한 뒤 턴 저장을 시도하는 방식은 사용하지 않는다.

## 구현 순서와 검증

1. 내부 관찰 계약과 검증: 관찰 목표/다음 초점 분리, 한 턴 여러 목표, 승인 범위/버전과 근거 참조 검사.
2. 분석·독립 검수의 버전 확장: 현재 v1과 새 계약을 구분하고, 기존 분석/검수 호출을 재사용.
3. 관찰 이력/현재 상태 저장과 동일 트랜잭션 연결: 새 마이그레이션 버전은 적용 당시 실제 이력과 의존 PR을 확인하고 배정.
4. 실제 컨텍스트·판정 공급과 음성 HTTP 검증: 원문 삭제 후 복원, 재전송, 동시 요청, 관찰 저장 실패 롤백.

다음 구현 단위는 1번 내부 관찰 계약이다. 공개 관찰 조회/지원 변경 API, 전체 턴 제한, 후속 난이도 계산은 이 첫 단위에 추가하지 않는다.
이 문서 작성 단계에서는 실행 코드·DB 마이그레이션·프롬프트를 변경하거나 새 테스트를 실행하지 않았다.

## 내부 계약 구현 — 2026-10-28

`RoleplayGoalObservationPlan.validateReferences`가 서버 컨텍스트와 분석·검수의 제안 결과를 대조한다.
세션·승인 시나리오 버전/참조·턴·후보·저장 버전과 분석/검수 계약 버전을 비교한다.
관찰 목표·학습 증거·다음 질문 목표가 승인 범위에 있는지, 판정 근거가 새 관찰 또는 서버가 공급한 기존 확정 관찰에 있는지 확인한다.
현재 턴과 기존 이력의 혼용, 동일 관찰의 중복, 근거 없는 달성, 판정 불가 결과는 거절한다.
한 턴에서 여러 목표를 관찰할 수 있으며, 관찰 목표와 다음 질문 목표가 같아야 한다는 제약은 없다.

이 검사는 참조 무결성만 다룬다. 관찰 내용과 활동 목표 달성의 의미 검수는 후속 공급 연결에서 수행해야 한다.
기존 이력은 서버가 같은 세션·승인 버전에서 조회해야 하며 이 계약은 조회·인증·DB 검증을 대체하지 않는다.
활동 목표 판정을 관찰 상태로 자동 계산하거나 모든 목표의 달성을 강제하지 않는다.

새 계약 테스트 30개와 기존 구조 검사 11개, 코드 형식 검사를 통과했다.
아직 실행 중인 음성 경로에는 연결하지 않았으며 프롬프트·DB·공개 API·프론트엔드 변경은 없다.
다음 동작은 기존 분석·독립 검수의 출력 계약을 버전과 함께 확장해 이 변경안의 입력을 공급하는 것이다.

## 분석·검수 v2 내부 계약 구현 — 2026-10-28

`GoalObservationOutput`에 분석의 `goal_observation`과 검수의 `goal_observation_review`를 정의했다.
분석은 `analysis-result/v2`, 검수는 `evaluation-result/v2`이며 출력 내부에도 해당 버전을 요구한다.
관찰은 턴·작은 목표·승인 증거 참조와 상태를 담고, 활동 목표 판정은 달성/진행 중/판단 불가 및 관찰 근거 목록을 담는다.
다음 질문의 초점은 기존 `next_strategy`에 유지한다. 관찰 상태를 전체 활동 달성으로 자동 변환하지 않는다.

`GoalObservationInput`은 서버가 공급한 승인 기준 참조/설명과 이전 확정 관찰을 전달한다.
참조와 승인 시나리오의 목표별 학습 증거가 일치해야 한다. 이전 관찰 조회의 세션·승인 버전 범위는 여전히 서버 공급자의 책임이다.
이는 승인 콘텐츠의 일관성 검사이며 아동 답변이 예시 문장과 정확히 일치해야 한다는 규칙이 아니다.

`RoleplayPromptFactory`와 `StructuredRoleplayTurnSteps`는 이 입력을 명시적으로 받았을 때만 v2 분석·검수 프롬프트와 파서를 선택한다.
후보 생성은 기존 `candidate-response/v1`을 사용하고 관찰 분석은 생성·검수 입력에 함께 전달한다.
분석/검수 v1 기본 경로는 유지하며 v1과 v2 출력이 섞이면 거절한다.
프롬프트에는 모든 작은 목표의 순차 통과나 정답 제공만으로 전체 달성을 확정하지 말라는 기준을 반영했다.
턴 제한에 따른 마무리 전략과 활동 목표 달성도 구분한다.

관찰 파서는 승인되지 않은 참조, 다른 턴/분석, 중복 관찰/판정 근거, 존재하지 않는 근거와 근거 없는 달성을 막는다.
검수는 동일한 분석 ID의 관찰과 활동 목표 판정을 모두 승인해야 PASS가 가능하다.
관찰 또는 판정이 근거 없으면 분석으로 돌아가며, 위험 입력/불명확한 입력의 기존 우선 처리는 유지한다.
원인 분석이 틀렸는데 후보 문장만 재생성하는 판정은 허용하지 않는다.
실행기와 Ready 생성도 분석/검수의 형식 및 분석 ID가 일치하는지 확인한다.

검증: 새 프롬프트 계약 테스트 33개, 실행기 경계 테스트 3개 추가를 포함한 관련 테스트 총 209개 통과.
정상 v2 턴은 기존 분석·생성·검수의 세 호출만 사용했다. 검수 시간 초과는 같은 분석·후보·입력으로 검수만 재시도했다.
관찰 검수 실패 후에는 새 분석 ID로 재분석하고 새 결과를 검수했다.
기존 음성 HTTP 28개 및 설정 7개도 포함하며 코드 형식 검사·차이 검사·저장 패치 역적용 검사를 통과했다.

LLM은 모의 제공자를 사용했다. 실제 모델의 판정 품질은 검증하지 않았다.
실제 승인 기준 참조/이전 관찰 공급자, v2 결과→관찰 변경안 변환, DB 저장과 운영 HTTP 조립은 아직 연결하지 않았다.
DB 마이그레이션·공개 HTTP 계약·프론트엔드 변경은 없다. 다음 작은 동작은 검수된 v2 결과를 관찰 변경안으로 변환하는 연결부다.

## 검수 결과→관찰 변경안 변환 — 2026-10-28

사용자가 선택한 ‘관찰 변경안 변환 연결’부터 이어서 구현했다.
`RoleplayGoalObservationMapper.toPlan(context, command, approvedTurn)`이 검수된 Ready 결과를 받는다.
저장 명령과 턴·후보 ID, 다음 질문 목표, 지원 수준, 응답 문장을 비교하고,
명령의 세션·시나리오/버전·저장 전 버전을 서버 컨텍스트에 대조한다.
승인 참조와 기존 관찰은 서버 컨텍스트에서 공급한다. 같은 승인 버전의 일관된 조회 책임은 공급자에게 있다.

관찰 목표·증거·상태와 활동 전체 판정/근거를 별도로 변환하고 기존 `validateReferences` 검사를 다시 수행한다.

## 턴·관찰·완료의 원자적 저장 — 2026-10-28

어느 단계든 실패하면 모두 취소한다. 재전송은 기존 결과를 반환하고 관찰·판정·보상을 다시 반영하지 않는다.

### 저장 구조

## 도움 이력과 충돌하는 지원 제안 차단 — 2026-10-28

근거는 통합 워크플로우 14절(1203, 1218행 부근)과 요구사항 LVL-14·17이다.
정답을 알려준 목표는 추가 유도를 중단하고, 지원 감소는 다음 목표의 시작 질문 등에 반영한다.
같은 목표에서 이미 제공한 지원을 낮춰 같은 질문을 반복하지 않는다.
연속 달성의 임의 횟수나 전체/목표별 고정 턴 수는 추가하지 않았다.

`RoleplaySupportDecisionRules.requireValidAnalysis`가 서버가 공급한 현재 목표별 노출 이력과 분석의 다음 전략을 대조한다.
PROBE_EVENT/EMOTION/CAUSE/ACTION 또는 ADVANCE_GOAL로 유도할 목표에 정답 제공 기록이 있으면 거절한다.
다른 목표로 옮겼다가 이미 정답을 알려준 목표로 돌아오는 제안도 해당 목표의 이력으로 검사한다.
현재 목표에 같은 학습 유도 전략을 유지하면서 지원 수준을 낮추는 제안도 거절한다.
다른 목표의 시작 수준은 현재 목표와 단순 비교하지 않고, 마무리 전략도 같은 목표 유도로 간주하지 않는다.
입력 확인/재지향 전략의 기존 계약은 유지한다. 전략/발화 의미 전체를 서버가 새로 판정하는 검사는 아니다.

분석 출력 파서에서 충돌을 INVALID_OUTPUT_FORMAT으로 반환해 후보 생성 전에 기존 분석 재시도를 사용한다.
정상 경로의 분석→생성→검수 3회와 기존 재시도/시간 예산은 유지한다.
DB 저장 전 실제 판정 공급자에서도 동일 규칙을 다시 검사한다. 검수 PASS나 명확한 관찰이 있어도
정답 제공 이력과 충돌하는 학습 유도 제안을 저장하지 않는다. 이 단계의 거절은 기존 ROLEPLAY_CONTEXT_UNAVAILABLE다.
관찰/완료/보상 저장 전 검사이며 기존 확정 턴·목표/지원·학습 기록을 바꾸지 않는다.

과거 명확한 관찰이나 정답 제공만으로 독립 도달/활동 완료를 자동 확정하지 않는다.
