## 이번에 한 일

서로 다른 작은 목표 2개를 힌트 없이 연속 달성하면, 아직 질문하지 않은 다음 목표의 시작 지원을 한 단계 낮춘다. 예를 들어 모델의 S2 제안을 생성 전에 S1로 보정하며 S0는 유지한다. 부분 이해·도움 요청은 연속성을 초기화하고 판정 불가는 연속성을 유지한다.

현재 목표의 승인된 필수 관찰과 사전 도움 이력으로 도달 방식을 대조하고, 생성·검수·저장까지 같은 정책과 근거를 전달한다. 원래 제안·적용 수준·정책·근거를 함께 저장하며 재분석·재전송으로 중복 차감하지 않는다. 같은 목표의 지원 상승은 한 번에 한 단계로 제한한다.

저장 입력 순번과 학습 횟수를 분리하여 `NOT_ASSESSABLE`이 지원 유도·전체 학습 턴 상한을 소모하지 않도록 했다. 저장 트랜잭션에서도 학습 횟수를 다시 확인하며 완료·보상·기록·발화 삭제를 함께 확정한다.

## 리뷰에서 봐주셨으면 하는 곳

- `RoleplaySupportApplication.apply/requireValid`: 생성 전 보정과 저장 전 동일 근거 재검증
- `RoleplayInputEvidence/RoleplaySupportHistory`: 현재 입력 목표의 필수 긍정 관찰·도움 이력 대조와 과거 불명 판정 처리
- `RoleplayGoalObservationStore`: 판정·보정 기록·근거의 원자적 저장 및 삭제
- `RoleplayCompletionService`: 확인된 학습 횟수에 따른 완료와 기존 요청 재전송·보상 중복 방지 유지

## 고민했던 점 · 다른 선택지

모델에 지원 감소를 직접 확정하게 하는 대신 원래 제안을 서버에서 보정하고 근거를 재검사한다. S1은 단서를 제공한 수준이므로 독립 도달로 간주하지 않는다. 여러 관찰 기준이나 같은 목표의 반복 달성을 서로 다른 목표의 달성으로 세지 않는다.

과거 판정을 확인할 수 없으면 학습 순번을 추정하지 않고 null로 두며 해당 학습 횟수 상한의 자동 적용을 보류한다. 입력 목표 판정 계약이 없는 이전 내부 호출 경로에는 기존 저장 순번 상한을 유지한다. 활동 목표 달성에 따른 완료는 별도다.

## 설정과 DB 변경

기본 정책은 목표 2개·`RESET_SEQUENCE`·`SUPPORT_DECREASE_V1`이다. 다른 기준으로 변경할 때는 정책 버전도 변경해야 하며 불완전한 설정은 거절한다. 기존 전체/목표별 턴 제한 값은 배포 설정으로 받는다.

V30은 입력 목표 도달 방식·지원 결정과 관찰 근거를, V31은 원래/적용 수준·정책과 적용 근거를 저장한다. 기존 V1~V24는 변경하지 않았다. 입력 흐름 PR과 병렬 머지·자동 배포가 가능하도록 두 PR에 동일한 V25~V31 파일을 포함한다. 먼저 배포된 PR이 전체 마이그레이션을 적용하고, 다음 PR은 같은 체크섬을 재사용한다. 원래 미커밋 검증본의 V26/V27을 V30/V31로 옮겼으므로 이전 로컬 검증 DB 이력을 그대로 재사용하지 않는다.
