# 역할극 S3 생성·검수 계약 정합성 개선

## 문제와 변경 결과

캐릭터 역할극에서 S3 직접 답 제공과 전략별 응답 유형 지침이 충돌했다. S3 후보에 ANSWER_TOO_DIRECT가 반환되어 재생성·재분석이 이어진 Dev 60초 요청을 계기로, 서버가 생성·검수의 공통 계약과 거절 근거를 검증하도록 변경했다.

- 다섯 학습 전략의 S3 응답은 ANSWER_REVEAL로 일치시킨다. 기존 정답 제공 이력에 올바른 유형이 반영되도록 하며 과거 데이터는 변경하지 않는다.
- 생성·검수에 지원 보정 후 동일한 목표·지원·응답 유형 계약을 전달한다.
- 검수 출력 v6에 nullable answer_directness_violation을 추가한다. 사유·발화자·인용·실패 코드·난이도 검사 결과를 검증하고, 요청별 native 스키마로 허용 사유를 좁힌다.
- 모순된 검수는 같은 후보를 다시 검수한다. 자동 PASS나 후보 재생성으로 바꾸지 않는다.
- 생성 출력 오류는 안전한 수정 조건으로 전달하고 새 후보에서 초기화한다.
- 질문/진술의 해석 기준을 정리하되 물음표 기반 강제 분류나 분석 승인 캐시는 추가하지 않는다.

## 보존한 동작

기존 60초 공유 예산·시도 상한·안전/입력 확인 우선순위·독립 검수를 유지한다. 외부 API와 DB 스키마는 변경하지 않는다. 정답 제공과 아동의 독립 달성은 구분한다. 프론트엔드 변경은 없다.

## 검증

- `./gradlew --no-daemon build`: 통과. 최종 전체 빌드 5분 12초.
- JUnit XML 합계: 2,891개 중 2,885개 통과, 실패·오류 0개, 실행 조건이 필요한 6개 건너뜀(실제 ML API 1개, FFmpeg 실환경 5개).
- 마이그레이션 가드: Bash 5.2 컨테이너에서 upstream/develop 기준 통과. macOS 기본 Bash 3은 연관 배열을 지원하지 않아 사용하지 못했다.
- 공개 금지 파일·값 검사 및 diff 공백 검사: 통과.
- Gitleaks v8.30.1: upstream/develop 이후 이번 작업 2개 커밋에서 비밀값 검출 없음.

S0~S3 × 학습 전략 조합, 직접성 거절의 인용·발화자·지원 수준 일치, 안전 우선·재분석 보존, 생성 오류와 검수 오류가 각각 같은 단계에서 재시도되는 경로를 검사했다. 과거 실험 진단 실행기도 새 파생 계약 필드와 nullable 출력 필드에 맞춰 검증했다.

실제 Elice 추가 호출·Dev 배포는 수행하지 않았다. 가짜 제공자 검사는 서버 제약·재시도 분기를 확인하며 실제 모델의 교육적 판단 정확성이나 성능을 증명하지 않는다.

## 지연 조사와 남은 확인

저장된 P1 세 건과 Dev 로그를 집계했다. 재시도 없는 P1도 19~22초였고, Dev 첫 검수까지의 외부 호출은 약 34.7초였다. 관찰 맥락·검수 자료·지침·출력 설명이 다음 정보량 축소 검토 대상이다.

이번 변경은 계약 검증 정보가 추가돼 첫 호출 입력량이 늘 수 있다. 재시도 감소·총시간 개선은 같은 대화와 목표·지원 이력으로 실제 모델을 재측정해야 한다. 입력 축소·모델 설정 변경은 적용하지 않았다.
