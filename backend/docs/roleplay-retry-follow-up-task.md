# 후속 Task: 역할극 LLM 재시도 관측과 전체 예산 정책

- 상태: 백로그. PR #49의 R5는 이번 리뷰 수정에서 보류한다.
- 공식 Task ID: 미배정. 기존 스프린트 Task ID를 임의로 사용하지 않는다.
- 배경: 분석 최대 3회, 후보별 생성·평가 최대 3회, 후보 최대 3개를 조합하면 한 턴의 LLM 단계 시도는 최대 21회다. 정상 경로는 3회다.
- 기존 지표 구현 커밋 `306f437`은 사용자 요청으로 revert한다. 아래 항목은 현재 구현이 아니라 후속 작업이다.

## 목적

기술적 재시도와 평가 탈락 후 재생성을 구분해 비용·지연·성공률을 관찰하고,
전체 시간·호출·비용 상한을 근거를 가지고 결정한다.

## 작업 범위

- [ ] 분석·생성·평가 단계별 시도 수와 시간, 실패 종류, 재시도 여부를 계측한다.
- [ ] 후보 재생성 수, 평가 거절 결정, 총 시도 수별 종료 사유를 계측한다.
- [ ] 단계 실행·실제 HTTP 송신·과금 횟수를 구분하고 관측 위치를 정한다.
- [ ] LLM 평가 PASS·TTS·DB 확정·HTTP 응답의 성공/시간 경계를 구분한다.
- [ ] 프로세스 종료 및 작업자가 돌아오지 않는 경우의 완료 표본 누락을 다룬다.
- [ ] 요청/아동/세션 식별자와 발화·프롬프트·후보·오류 원문 없이 집계하며 태그 종류를 제한한다.
- [ ] 지표 조회와 수집·보관 방법을 결정한다. Actuator 노출 범위·접근 권한을 함께 검토하고 실제 조회를 확인한다.
- [ ] 정확한 비용 판단이 필요하면 모델별 토큰 사용량 및 과금 자료를 추가한다.
- [ ] 추가 시도의 성공률 기여·지연·사용량을 비교해 전체 호출 상한을 합의한다.
- [ ] 상한이 확정되면 설정 주입, 한도 도달 시 기존 복구 경로, 관측 후 조정 절차를 구현한다.

## 유지할 조건과 미정 정책

- 이번 보류에서는 기존 단계/후보 제한과 전체 최대 60초를 변경하지 않는다.
- 전체 호출 상한 9회 등은 검토 예시일 뿐 확정값이 아니다.
- 한도에 맞추기 위해 안전 검사나 평가를 생략하거나 미검증 후보를 전달하지 않는다.
- 관측 실패가 정상 응답·재시도 동작을 바꾸지 않도록 한다.
- HTTP 시간 초과와 실제 작업 종료를 구분하며, 계측을 위해 처리권을 먼저 해제하지 않는다.
- R3의 CloudFront 응답 여유 문제는 별도 보류 항목으로 유지한다.

## 완료 기준

- 정상·기술적 실패·평가 거절·한도 도달·시간 초과의 계측 의미를 문서화하고 적절히 검증한다.
- 실제 실행 후 권한 있는 조회 경로에서 지표를 확인할 수 있다.
- 수집/보관 여부와 프로세스 재시작 시 데이터의 경계를 명확히 한다.
- 전체 상한을 변경한다면 정책 근거와 기존 대비 성공률·지연·사용량 영향을 기록한다.
