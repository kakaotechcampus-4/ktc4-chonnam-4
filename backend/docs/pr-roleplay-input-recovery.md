## 이번에 한 일

음성 인식·입력 의미 판정에서 새 음성 입력이 실패하면 학습 턴을 저장하지 않고 재입력을 안내한다. 세 번째 실패부터 텍스트 입력을 권유하면서 음성 선택은 유지한다. 같은 요청 키·같은 입력의 재전송은 재집계하지 않고, 같은 키에 입력을 바꾸면 409로 처리한다.

텍스트 답변을 `POST /api/v1/roleplay-sessions/{sessionId}/text-inputs`로 제출할 수 있다. 음성과 같은 세션·목표·체크포인트를 사용하며 STT를 건너뛴다. 텍스트 거절은 음성 실패 횟수를 늘리지 않는다. 검증된 입력 품질은 분석·검수·DB에 전달하고 표준 발화와 함께 삭제한다.

- 검증 근거가 없거나 불완전할 때 분석·검수·학습 저장을 시작하지 않는 경계
- 원문을 공개 응답·로그에 노출하지 않는 입력 처리와 품질 기록의 삭제 시점
- 최신 develop의 최대 턴 종료·보상 처리 및 API 활성화 설정 조건 유지

## 고민했던 점 · 다른 선택지

입력 재시도를 학습 실패와 분리해 목표 달성·지원 상태가 기술 오류 때문에 바뀌지 않도록 했다. 입력 실패 결과는 DB에 보관하여 재시작과 재전송에서도 중복 집계를 막는다. 텍스트 글자 수의 제품 기본값은 임의로 정하지 않고 배포별 처리 상한을 명시적으로 받는다.

## 실행 설정

기존 HTTP 활성화·업로드·전체/목표별 턴 제한 설정에 더해 텍스트 API는 `ROLEPLAY_TEXT_ENABLED=true`와 양수 `ROLEPLAY_TEXT_MAXIMUM_CHARACTERS`가 필요하다. `ROLEPLAY_STT_CONFIDENCE_THRESHOLD`의 기본값은 0.40이다. 입력 검사기는 표준 발화와 의미 보존·안전·정제 신뢰도·마스킹 여부를 제공해야 한다.

V1~V24는 변경하지 않았다. 새 V25~V29의 순서와 원래 미커밋 검증본의 대응은 [입력 복구 계약](roleplay-input-recovery.md)에 정리했다. 원래 검증본의 로컬 DB 이력을 이 브랜치에 그대로 재사용하지 않는다.

## 후속 작업과 프론트엔드 연동

프론트엔드는 수정하지 않았다. 역할극 답변 화면에서 JSON `{"text":"답변"}`과 아동 세션·CSRF·`Idempotency-Key`로 텍스트 API를 호출해야 한다. 새 입력에는 새 요청 키, 같은 입력 재전송에는 동일 키·동일 원문을 사용한다. `REINPUT_REQUIRED`와 `SUGGEST_TEXT_KEEP_VOICE`를 표시하면서 음성 선택을 유지하고 처리 중·충돌·재시도·중단 응답을 처리해야 한다.

파일 손상·형식·크기·길이·검사 도구 오류의 HTTP 복구 연결은 음성 검증 브랜치에서 이관한다. 실패 원장의 완료 즉시/미완료 24시간 삭제와 입력·정리 경합 제어는 수명주기 브랜치에 남아 있다. 현재 브랜치만으로 해당 사용자 정책 전체가 완료된 것은 아니다.

운영 입력 검사기와 실제 STT/LLM/TTS·브라우저 연동은 미검증이다. 실제 제공자 연동과 프론트엔드 대응 없이 Task 전체 완료로 판단하지 않는다.
