## 이번에 한 일

독립 검수가 `REANALYZE`를 반환하면 기존 실행기는 이전 분석을 비우고 다시 분석했지만, 재분석 프롬프트에 수정 대상인 직전 분석을 전달하지 않았다. 거절된 분석·후보·검수를 요청 내부 이력에 함께 보존하고, 다음 분석 요청의 `retry.failed_analysis`로 가장 최근의 실패 분석을 전달한다.

- 기존 `failure_codes`, `focus`, `do_not_assume`와 함께 전달한다. 다른 턴의 분석이나 다른 후보의 검수를 연결하는 경우를 차단한다.
- 실패 분석은 수정할 자료이며 확정 사실·지시·목표 달성 근거로 취급하지 않도록 프롬프트에 명시한다. 새 분석은 현재 `analysis_id`를 사용한다.
- 유효한 분석이 없는 최초 형식 오류 재시도에는 `failed_analysis`를 넣지 않으며, 깨진 출력 원문을 전달하지 않는다.
- 분석 프롬프트 버전은 `roleplay-cause-analysis/v3`, 출력 스키마는 기존 `analysis-result/v2`다. 기존 v2 본문에 재분석 안내 리소스를 결합해 지원 정책 변경과 함께 적용되도록 했다.
- 기존 재분석·재생성·동일 후보 재평가 횟수, 공유 60초 예산, 전달 게이트·저장·보관 정책은 유지한다. HTTP 계약·DB 스키마 변경은 없다.

기존 체크포인트 경로는 재사용했다. PostgreSQL 통합 테스트를 추가해 C1 거절 → 재분석 → C2 승인·확정 → 응답 공개 실패 → 같은 요청 재전송에서 C2 복구를 연결해 검증했다. 체크포인트 기능 자체를 새로 구현한 변경은 아니다.

## 고민했던 점 · 다른 선택지

재시도 횟수가 제한된 요청 내부 이력에 분석을 추가했다. 실패 분석을 DB에 영구 저장하거나 아동 응답에 노출하는 새 계약은 만들지 않았다. 프롬프트에는 이미 사용하는 명시적 `analysisSection`으로 투영해 내부 지원 보정 필드까지 자동 직렬화하지 않는다.
