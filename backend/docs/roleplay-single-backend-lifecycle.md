# 단일 백엔드의 종료·재전송 계약

S3-JIN-02, 2026-10-28, 기준 develop `9f6ffa5`.
이전에 PR #63에서 확인한 단일 EC2/nginx/backend 구조를 전제로 한다. `63e4314` 이후 이 기준까지 deploy 변경은 없다.

## 운영 전제

같은 업무 DB에 backend1개만 연결한다. 별도 복제본·구/신 서버 동시 운영에는 메모리 처리권이 공유되지 않는다.
서버 증설 전에 DB 등 공유 처리권과 장애 복구 정책이 필요하다. 원본 Task의 DB PROCESSING 소유권은 미구현이다.
배포 잠금은 배포를 직렬화할 뿐 음성 요청의 처리권을 대신하지 않는다.

## 종료 설정

- 턴 전체 처리 예산: 기존 최대60초 유지.
- Spring 종료 단계 대기: 70초.
- backend 컨테이너 종료 유예: 90초.

정상 종료 시 새 요청 수락을 중단하고 기존 HTTP 요청이 마무리될 시간을 준다.
워커 파괴 시점은 기존 HTTP 요청 종료 뒤이며 워커의 shutdownNow 코드는 바꾸지 않았다.
70/90초는 종료 여유이며 요청 TTL이나 AI 예산을 늘리는 값이 아니다.
강제 종료·호스트 장애·무중단 배포까지 보장하는 설정은 아니다.

## 재전송

인증·소유권 확인 후 DB에 확정 결과가 있으면 같은 키·지문의 기존 결과를 반환한다. AI/음성/턴 저장을 반복하지 않는다.
확정 결과가 없으면 다시 처리할 수 있어, 저장 전 프로세스 장애의 외부 AI 호출은 반복될 수 있다.
처리 중 같은 입력은202, 같은 키의 다른 입력은409다. 원래 입력을 자동 취소·교체하지 않는다.
프론트엔드는 원래 키·본문/음성을 유지하고 확정된 완료를 서버에서 확인해야 한다.

## 검증

RoleplayShutdownTest2개가 실제 설정의60<70<90 관계와 내장 Tomcat의 요청 처리 중 정상 종료·워커 종료 순서를 확인한다.
이는 테스트 servlet/실제 워커 팩토리와 runner를 사용한 검사이며 실제 EC2·Docker 종료나 전체 역할극 HTTP 종료 검증은 아니다.
이번 선별 검증은 배정/음성/원자 저장을 포함해 총16개 통과했다. 전체 회귀나 운영 배포는 실행하지 않았다.
