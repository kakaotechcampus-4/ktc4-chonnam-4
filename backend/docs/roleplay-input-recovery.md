# 음성 실패 집계 계약

이 브랜치는 `S6-JIN-01`의 입력 품질·실패 집계·텍스트 복구를 담당한다. 기반은 원본 develop `ccfdff0`이다. 지원 조정·실제 음성 검증·입력 수명주기는 별도 목적 브랜치로 이관한다.

## 집계와 학습 상태

새 음성 입력의 최종 실패만 누적하며, 세 번째 실패부터 텍스트 입력을 권유하고 음성 선택을 유지한다. 무음·저신뢰·신뢰도 미제공·STT 실패·의미 불확실·파일 및 검사 오류·크기/길이 초과는 실패 분류에 포함한다. 학습 오답·목표 달성·지원 상태와는 별도 기록이다. 텍스트 입력 거절을 음성 실패로 집계하지 않는다.

저장 계약은 세션과 요청 키에 대해 한 행만 허용한다. 신뢰도는 저신뢰 판정의 실제 근거가 있을 때만 보관하며 과거 값은 추정하지 않는다. 전체 지문을 얻지 못한 크기 초과는 지문을 비워 저장할 수 있지만 다른 사유는 지문을 요구한다. 같은 요청 키·같은 지문의 재전송은 실패를 더하지 않고 복원한다. 같은 키로 입력을 바꾸면 충돌로 처리한다. 과거 실패를 다시 조회할 때도 현재 누적 횟수에 따른 텍스트 권유를 반환한다.

## 브랜치별 마이그레이션 정리

원래 미커밋 검증본의 변경을 목적별 브랜치로 나누면서 새 마이그레이션 순서를 정리한다. 원본 develop에 이미 존재하는 V1~V24는 수정하지 않는다. 아래 파일은 이 브랜치에서 새로 추가한 계약이며, 이전 로컬 검증 DB에 그대로 재적용하지 않는다.

| 이 브랜치 | 원래 미커밋 검증본 |
|---|---|
| V25 실패 원장·누적 | V25 |
| V26 저신뢰 근거 | V28 |
| V27 허용 실패 사유 | V30·V31·V33·V34의 최종 허용 목록 |
| V28 지문 없는 크기 초과 | V32 |
| V29 정상 입력 품질 | V29 |

실행 경로에는 STT·의미 판정의 입력 거절 → 실패 저장 → 공개 재입력 응답을 연결했다. 저신뢰 근거는 실제 판정값을 저장하며 학습 턴·목표 관찰·지원 상태는 갱신하지 않는다. 새 실패만 마지막 활동 시각을 갱신하고 재전송은 갱신하지 않는다. 실패와 성공 턴은 같은 요청 키를 함께 점유할 수 없으며 아동 삭제 시 실패 원장·누적도 삭제한다.

응답은 `REINPUT_REQUIRED`이며 세 번째 실패부터 `SUGGEST_TEXT_KEEP_VOICE`, 이전에는 `REQUEST_NEW_INPUT`을 반환한다. 사유별 승인 안내가 없으면 “다시 한 번만 말해줄래?”를 사용한다. 프론트엔드는 텍스트 권유를 표시하면서 음성 선택도 유지해야 한다. 프론트엔드는 수정하지 않았다.

텍스트 입력 API와 품질 전달을 연결했다. 파일 검사 실패의 HTTP 연결은 음성 검증 브랜치에서, 활동 완료/24시간 경과에 따른 실패 삭제는 수명주기 브랜치에서 이관한다. 현재 커밋만으로 전체 입력 복구가 완료되지는 않는다. 최신 develop의 턴 제한 설정·API 활성화 조건은 유지했다.

## 이번 연결의 검증

실제 PostgreSQL에서 실패 저장·동시 요청·재전송·성공 키와의 충돌·저장 롤백·아동 삭제 및 V24/V25 이력에서의 마이그레이션을 검증했다. HTTP 재입력·3회 권유·음성 유지·설정 활성화·최대 턴 완료 회귀 검사와 입력 파이프라인·체크포인트·삭제 검사도 통과했다. `spotlessCheck` 통과. 실제 외부 STT와 브라우저 연동 검증은 포함하지 않는다.

## 텍스트 입력과 품질 검증

`POST /api/v1/roleplay-sessions/{sessionId}/text-inputs`에 아동 세션 인증·CSRF·`Idempotency-Key`와 JSON `{"text":"답변"}`을 전달한다. 음성 실패 전에도 사용할 수 있으며 같은 세션의 턴·목표·요청 키를 공유한다. 같은 키로 입력 방식이나 원문을 바꾸면 409 충돌이다. 텍스트 거절은 음성 실패를 늘리지 않는다. 성공 텍스트 처리에는 STT를 호출하지 않으며 이후 음성 입력도 계속 가능하다.

`ROLEPLAY_HTTP_ENABLED=true`와 `ROLEPLAY_TEXT_ENABLED=true`일 때만 텍스트 API를 등록한다. 이 경우 `ROLEPLAY_TEXT_MAXIMUM_CHARACTERS`를 양수로 명시해야 시작할 수 있다. 이는 배포 처리 상한이며 제품 글자 수의 확정 기본값이 아니다. 길이는 유니코드 코드포인트로 센다. 기존 전체·목표별 턴 제한 설정도 필요하다.

입력 검사기는 정제된 표준 발화와 의미 보존·안전·개인정보 마스킹 여부·정제 신뢰도의 판정 근거를 반환해야 한다. 검사 장애나 빠진 필수 근거는 재시도 안내로 반환하고 분석·검수·학습 저장을 시작하지 않는다. 의미를 보존하지 못한 입력은 재입력, 위험 입력은 중단 안내로 처리한다. 운영 입력 검사기 구현은 여전히 필요한 의존성이다. 테스트 제공자의 판정값은 운영 연동 완료를 뜻하지 않는다.

검증된 입력 방식·STT/정제 신뢰도·실패 횟수 스냅샷은 분석·검수에 전달하고 V29의 `roleplay_turn.input_quality`에 저장한다. 품질 기록은 표준 발화와 함께 활동 완료 즉시 또는 미완료 마지막 활동 24시간 경과 시 삭제한다. 과거 입력의 품질 정보는 추정하지 않는다. STT 기준은 기본 0.40이며 `ROLEPLAY_STT_CONFIDENCE_THRESHOLD`로 설정할 수 있다.

프론트엔드 후속 작업: 텍스트 제출을 위 API에 연결하고 음성과 같은 세션을 유지한다. 새 입력에는 새 요청 키를 사용하며 같은 요청 재시도에는 동일 키·동일 원문을 사용한다. 공개 `status`·`action`으로 재입력·재시도·중단·처리 중·충돌을 처리하고, 텍스트 권유 후에도 음성 선택을 유지한다. 화면과 실제 제공자를 통한 종단 검증은 남아 있다.

## 브랜치 회귀 검증 완료

2026-10-31 제품 코드 `34e46f8`에서 `./backend/gradlew -p backend --offline --no-daemon spotlessCheck build` 통과. 99개 클래스·1,576개 검사, 실패·오류·건너뜀 모두 0이다. 전체 XML 결과는 작업 백업 `S6-JIN-01-input-recovery-34e46f8-results`에 보존했다. 이후 문서 정리만으로 같은 검사를 반복하지 않는다.

지원 조정 브랜치는 동기화한 develop `ccfdff0`에서 별도로 준비한다. 지원 이력 스키마는 미사용 번호 V30·V31로 이관하며 이 브랜치의 실패 원장·품질 스키마에 의존하지 않도록 확인한다. 반대로 실제 파일 검증과 입력 수명주기 브랜치는 이 브랜치의 실패 저장·공통 입력 계약을 필요로 하므로 적용 순서를 PR에 명시한다. 지원 조정 이관에서 최신 develop의 전체 턴 종료 처리와 생성/검수 조건을 유지해야 한다.
