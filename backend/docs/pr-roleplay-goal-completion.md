# 역할극의 복수 목표 근거와 활동 달성 종료 연결

## 이번에 한 일

아동이 한 발화에서 여러 세부 목표의 근거를 표현하거나 여러 턴에 나누어 표현했을 때, 현재 질문 목표와 전체 목록 통과를 활동 종료의 추가 조건으로 삼지 않도록 캐릭터 분석·검수 정책을 정리했습니다.

활동 달성으로 분석되면 서버가 생성 전에 현재 목표·지원 수준의 마무리 전략으로 연결합니다. 독립 검수는 달성 근거와 응답을 계속 검사하며, 저장 단계에서도 달성 결과에 마무리 전략과 응답 유형이 모두 있어야 완료합니다. 분석·생성·검수의 기존 호출 수, 공유 60초 예산, 재시도 상한을 유지합니다.

## 리뷰에서 봐주셨으면 하는 곳

- `RoleplayActivityCompletion`: 목표별 관찰·현재 학습 상태·활동 판정은 바꾸지 않고 달성 제안의 다음 전략만 연결합니다. 판정 불가 입력의 달성은 거절합니다.
- `RoleplayCompletionService`: 달성인데 계속 질문하는 내부 결과가 턴·관찰·보상으로 확정되지 않도록 같은 트랜잭션에서 차단합니다.
- 복수 목표·과거 관찰 회귀 검사와 실제 PostgreSQL·HTTP 완료/롤백/재전송 검사입니다. 기존 합성 제공자의 달성 응답도 마무리 계약에 맞췄습니다.

## 고민했던 점 · 다른 선택지

긍정 관찰 개수나 전체 목표 목록을 서버가 세어 자동 달성을 선언하는 방식은 사용하지 않았습니다. 승인된 활동 목표·난이도에 대한 의미 판단과 독립 검수를 유지하고, 이미 제안된 달성이 다음 질문으로 이어지는 불일치를 서버에서 막았습니다.

## 검증과 남은 범위

검사 실행 결과는 `roleplay-goal-completion.md`의 최종 검증 기록을 따릅니다. 로컬 검사는 합성 AI와 실제 PostgreSQL을 사용하며, 실제 모델의 의미 판단 정확도와 지연 개선을 입증하지 않습니다.

추가 LLM 호출·DB 마이그레이션·공개 API 변경은 없습니다. 프론트엔드 변경은 없으며, Dev 배포 후 기존 활동 상태 조회의 `COMPLETED`를 화면이 반영하는지는 종단 확인이 필요합니다. S3 지원 종료 정책과 세션별 목표 판정 관측 보고서는 별도 범위입니다. 원문이 없었던 과거 Dev 시간 초과의 반려 사유는 아직 미확인입니다.
