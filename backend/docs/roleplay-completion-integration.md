### 활동 완료·보상과 목표 달성의 분리

- 승인된 활동 목표를 달성하거나, 서버에 설정된 최대 턴에 도달해 역할극을 정상 마무리하면 활동 완료·스탬프 1회를 확정한다.
- 최대 턴 종료로 활동이 완료돼도 학습 목표를 달성한 것으로 바꾸지 않는다. 실제 목표별 관찰과 도움 이력을 보존하고, 제한 턴 내 미도달은 난이도 계산용 최종 결과에서 `NOT_ACHIEVED`로 구분한다.
- 정답을 제공한 결과도 독립 도달로 바꾸지 않는다. 기존 `SUPPORTED_NOT_ACHIEVED` 구분을 보존한다.
- 스탬프는 활동 완료에 대한 보상이다. 지급 여부·`ActivityStatus.COMPLETED`·세션 종료 상태를 학습 목표 달성 판정이나 난이도 상향의 근거로 대체하지 않는다.
- 자발적 중단은 완료·보상 없이 마지막 확정 단계부터 재개한다. 기술·안전 종료는 기존의 완료·보상 및 난이도 평가 제외 정책을 따르며, 이 문서 정리로 해당 종료 경로의 구현이 완료된 것은 아니다.
- 클라이언트의 완료 표시, 검수 PASS, `CLOSING` 응답 문구만으로 완료를 확정하지 않는다. 목표 달성 또는 서버가 확인한 최대 턴 종료 조건이 필요하다.
- 최초 결합 활동은 퀴즈 결과가 먼저 확정돼야 한다. 퀴즈만 완료했다고 최초 결합 활동의 완료·보상을 확정하지 않는다.

근거: 기능 요구사항 `SES-07`, `RWD-01~06`, `LVL-24~29`, 사이트맵 `C-RP-06`·`C-DONE-02`와 역할극 마무리 이후 스탬프 흐름, 이번 사용자 확인.
최대 턴의 구체적인 숫자를 이번 정책 확인으로 확정한 것은 아니다.

### 후속 역할극 난이도 기준 보존

후속 난이도는 가장 최근 완료한 유효 역할극의 목표별 수행 근거로 판단한다. 활동 완료·스탬프 지급만으로 모든 목표를 달성했다고 처리하거나, 최대 턴 종료를 무조건 난이도 유지로 처리하지 않는다.

| 근거 | 다음 역할극 난이도 |
|---|---|
| 유효 목표 2개 미만, 근거 부족 또는 계산 실패 | 현재 유효 난이도 유지 |
| 점수 50% 미만 또는 정답 제공·미도달에 해당하는 고유 목표가 유효 목표의 절반 이상 | 한 단계 하향. L1에서는 유지 |
| 기존 유지 조건 및 다른 확정 조건에 해당하지 않는 결과 | 현재 유효 난이도 유지 |
| 80% 이상·모든 유효 목표 S0~S2 도달·정답 제공 없음 | 기존 상향 후보 규칙 적용. 기본적으로 2회 연속 충족 후 한 단계 상향 |

제한 턴 내 미도달은 기존 목표별 점수표의 0점·`NOT_ACHIEVED`를 보존한다.
기술 오류와 비학습 종료의 제외 규칙, 초기 지원 수준에 따른 점수 정규화, 하향 우선순위 및 정책 버전도 기존 계약을 따른다.
현재 대화 중의 지원 수준 S와 다음 활동의 시나리오 난이도 L을 혼용하지 않는다.
운영 정책의 빠른 상향 예외를 이번 충돌 해결로 새로 활성화하지 않는다.

### 남은 구현·검증

1. 최대 턴 도달과 정상 마무리를 서버의 저장 상태·설정으로 확인하고, 목표 달성 판정과 별개의 완료 근거로 전달한다. 판정을 `ACHIEVED`로 바꿔 우회하지 않는다.
2. 최대 턴 종료에서도 마지막 턴·관찰·활동 완료·보상·기록·세션 종료·표준 발화 삭제를 같은 트랜잭션에서 확정한다. 재전송·동시 요청의 1회 확정과 전체 롤백을 유지한다.
3. 종료 후 목표별 최종 결과·지원 근거를 기존 후속 난이도 정책에 연결하고, 판정·다음 시나리오 난이도·점수율·연속 후보 수·정책 버전을 저장·적용한다.
4. 최대 턴으로 완료·보상되면서도 미달 목표가 달성으로 바뀌지 않는 경우, 근거에 따른 유지·하향, 기술 제외, 중복 지급 방지와 저장 실패 복구를 검증한다.

이 현황 절은 다섯 번째 충돌 파일을 정리할 때 작성했다. 이후 나머지 충돌 정리·공유 호출 예제 동기화와 검증을 진행하며, 위 최대 턴 연결·후속 난이도 계산의 미구현을 완료로 바꾸지 않는다.

마무리 문구나 후보 검수 PASS만으로 활동 목표가 달성됐다고 판단하지 않는다.

#### 기존 작업 기준의 구현

기존 작업 기준 `63e4314`의 `Activity`에는 완료·보상 시각 컬럼이 있으나 이를 확정하는 업무 서비스·완료 API가 없었다.
학습 기록 테이블·생성 서비스와 완료 전용 status 조회도 없다. `ActivityDetailResponse`의
sessionSummary·learningRecord는 아직 null이다. 이 세션 종료 메서드는 활동 완료 전체를 대신하지 않는다.

#### 공급 Task와 연결할 순서

활동 완료·스탬프·학습 기록은 S6-BAE-01/02의 연동 대상이다. 아래는 필요한 계약이며 현재 실행 경로가 아니다.

1. 인증·아동/활동 소유권과 서버의 완료 가능 상태를 확인한다.
2. 외부 AI 호출 없이 짧은 트랜잭션을 열고 활동 → 아동 → 세션 순서로 필요한 행을 잠근다.
3. 완료가 별도 공개 쓰기 요청이라면 키와 입력을 비교한다. 같은 요청은 확정 결과를 반환하고 다른 입력은 충돌 처리한다.
   서버 자동 완료라면 원래 턴/문항 요청의 재전송과 활동 단위의 1회 확정을 연결한다.
4. 활동 상태·완료 시각·스탬프 지급 시각·활동별 학습 기록 1개·멱등 결과 참조를 원자적으로 확정한다.
5. 정상 완료 경로에서 위 종료 메서드를 같은 트랜잭션 안에서 호출해 세션 종료와 표준 발화 삭제를 묶는다.
6. 커밋 후에만 완료 성공을 응답한다. 후속 리포트 생성 성공을 기다려 표준 발화 삭제를 미루지 않는다.

정상 완료는 아래 사용자 재확인의 ‘각 역할극 활동 목표 달성’을 따른다.
최대 턴 수·기술/안전 종료의 저장 가능한 필드와 공개 API 경로는 이 문서에서 새로 정하지 않는다.
특히 안전 종료는 사건 메타데이터 미저장 정책과 별도 정합성 확인이 필요하며, 정상 종료 메서드의 검증을

#### 실제 저장 메서드의 연결 위치

`JpaRoleplayCheckpointStore.commit()`는 `PROPAGATION_REQUIRES_NEW`로 턴과 체크포인트를 저장한다.
`RoleplayCheckpointedTurnExecutor.confirmed()`까지 반환됐을 때는 그 트랜잭션이 이미 확정된 상태다.
호출자 메서드에 `@Transactional`만 붙여도 내부 REQUIRES_NEW 저장까지 같은 트랜잭션으로 묶이지 않는다.
이를 위해 `commitInCurrentTransaction(command, deadline)` 진입점을 추가했다.
기존 `commit`의 REQUIRES_NEW 동작은 유지하고 새 진입점만 MANDATORY로 호출자의 트랜잭션에 참여한다.
동일 스레드의 활성 트랜잭션이 없으면 새 진입점은 거절한다. 잠금·재조회·버전·기한 검사와 실제 저장은 같은 내부 구현을 쓴다.

마지막 턴과 정상 완료를 함께 확정하는 설계에서는 다음을 저장 어댑터의 같은 트랜잭션 안에 연결한다.

1. 기존 활동 → 아동 → 세션 잠금과 동일 요청 재조회·버전 검사를 유지한다.
2. 승인된 새 턴을 저장하고, 해당 턴에 근거한 목표 상태를 반영한다.
3. 서버의 활동 목표 달성 판정이 완료인 경우 공통 완료 서비스의 역할극용 진입점과
   `completeNormallyAndDelete`를 호출한다. 별도 REQUIRES_NEW나 커밋 후 이벤트로 쪼개지 않는다.
4. 마지막 flush·deadline 검사 이후에만 커밋한다. 어느 저장이 실패하든 새 턴·목표 상태·완료·보상·기록·삭제를 함께 취소한다.

호출자 트랜잭션에 참여하는 저장 진입점을 바탕으로 실제 완료 서비스의 내부 연결까지 추가했다.
HTTP 호출 연결은 추가했지만 실제 목표 판정 공급은 아직 없으므로 운영 경로 전체가 실행되는 것으로 보지 않는다.
기존 요청 replay 분기는 상태 변경에 재진입하면 안 된다.
현재 `RoleplayCheckpointCommand`는 후보·문구·목표/지원·번호를 전달하지만 활동 목표 달성 판정은 담지 않는다.
`AnalysisResult.learningState`는 현재 목표 중심의 분석이며 모든 목표의 영속 관찰 집계를 대신하지 않는다.
`CLOSING`을 완료 신호로 취급하거나, `currentMicroGoalId`를 활동 전체 달성으로 해석하는 임시 코드를 추가하지 않는다.

완료·보상·기록 본체는 S6-BAE-01/02의 공급 범위다. S3-JIN-02는 승인된 판정/저장 계약을 소비해
동일 요청 재조회, 충돌, 1회 확정, 저장 실패 롤백을 연결·검증한다. 목표 관찰 모델 전체를 이 Task로 확대하지 않는다.
