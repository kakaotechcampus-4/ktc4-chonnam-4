## 결론

## 축소 형태에서 생긴 일

1. 최초 생성: `응… (잠깐 고개를 숙인다)`
   - 검수는 분석 자체를 모두 승인했다.
   - 후보에 ANALYSIS_RESPONSE_MISMATCH, MISSING_QUESTION, NOT_ANSWERABLE을 반환했다.
   - 수정 지시에 감정을 묻는 질문을 덧붙이라고 요구했다.
2. 두 번째 생성: `응, 그러다 자리에 앉았어. 그때 내 얼굴은 어때 보였어?`
   - 분석은 다시 모두 승인했다.
   - 후보에 ANALYSIS_RESPONSE_MISMATCH, NOT_ANSWERABLE을 반환했다.
   - 얼굴 대신 발표 중 어떤 기분이었는지 묻도록 요구했다.
3. 세 번째 생성: `응, 말이 안 나와서 앉았어. 발표할 때 어떤 기분이었을까?`
   - 검수 PASS. 자동 기대값인 GOAL_ACHIEVED, ADVANCE_GOAL, 길이 60자 이하를 충족했다.

## 사람 검토에서 남은 문제

- 캐릭터 생성 지침은 S0의 소리·행동과 질문 없는 반응을 허용한다. 검수 지침도 질문이 반드시 필요한 것은 아니라고 명시한다. 따라서 질문이 없다는 사실만으로 MISSING_QUESTION을 부여하는 것은 이 정책과 충돌한다. 첫 후보의 감정 단서가 충분하고 자연스럽게 반응 가능한지는 별도의 의미 판단이며, 자동 승인할 근거는 아니다.
- 두 번째 후보의 표정 질문은 시나리오에 주어진 사건과 캐릭터 자기 몸 표현을 구분해 판단해야 한다. 이번 검수의 거절이 전적으로 타당한지 단건으로 확정하지 않는다.
- 최종 후보는 자동 검수를 통과했지만, 캐릭터가 아동에게 자기 감정을 맞히게 하는 문답으로 흐를 우려가 있다. 생성 지침은 교사처럼 정답·감정을 묻는 방식을 금지한다. PASS·기대값 3/3만으로 역할·교육적 품질을 승인하지 않는다.
- compact 분석은 현재 목표 GOAL_ACHIEVED와 primary_gap=MISSING_EMOTION을 함께 반환했다. 감정은 다음 목표이므로 현재 목표의 격차를 나타내는 계약과 맞는지 별도 확인할 항목이다. 자동 기대값 세 항목은 이 관계를 검사하지 않는다.
- native JSON Schema는 이번 7개 호출의 구조 검사를 통과했다. 구조 준수만으로 질문 강제·역할 변화 같은 의미 판단 오류가 방지되지는 않았다.
- 두 재생성은 분석 거절에 따른 재분석이 아니다. 이번 결과로 새 세부 재분석 사유 전달 경로의 실모델 효과를 입증하지 않는다.

## 다음 검증·수정 범위 제안

먼저 이번 실제 후보를 고정한 반례로 질문 없는 충분한 단서, 단서가 불충분한 대사, 캐릭터의 자연스러운 질문, 교사식 감정 맞히기를 구분하는 검수 기준을 설계한다. 질문이 없다는 이유의 거절에는 서버가 확인할 수 있는 정책·사유 계약을 검토하되, 잘못된 검수 결과를 PASS로 강제 변환하지 않는다. 재생성 지시가 생성 정책과 충돌하는 경로도 함께 점검한다. 설계를 승인받은 뒤 구현하며, 추가 실제 호출은 아직 하지 않았다.

서버의 60초 장애 입력 `도와줄까`는 이번 P1과 다르다. 그 실패가 해결됐다는 근거로 사용하지 않는다. 역할·검수 정합성 검증 후 해당 사례와 추가 상황으로 확장하고, 이후 Dev에서 입력 검사·TTS·저장까지 포함한 전체 HTTP 시간을 관측한다.
