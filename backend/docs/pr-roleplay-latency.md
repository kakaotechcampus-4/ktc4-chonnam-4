# 캐릭터 역할극 입출력 축소와 검수·재시도 정합성 개선

## 연결 Task

- Task Issue / 대표 Slice Issue: 별도 번호 미지정.
- 확인한 범위: 캐릭터 모델 출력 축소, 독립 검수와 재시도 근거 연결, S0 단서·역할 정책의 서버 계약, 로컬 회귀와 제한된 실제 모델 검증.
- 남은 범위: 여러 입력·반복의 안정성, 실제 Dev 실패 맥락과 입력 검사·음성·저장을 포함한 HTTP 관측.

## 이번에 한 일

캐릭터 분석·검수의 정책 차이와 근거가 부족한 거절로 재분석·재생성이 반복되며 60초 예산을 소모했다. 서버가 이미 아는 식별자·관찰 참조를 모델이 반복 출력하는 비용도 컸다.

- 캐릭터 분석·생성에 작은 native JSON Schema 출력을 적용하고, 요청에 고정된 식별자·관찰 참조·후보 메타데이터를 서버에서 복원한다. 복원 후 기존 업무·지원·안전 검증을 유지한다.
- 분석·검수가 같은 목표 진행·도움 제안·부분 이해 정책을 사용한다. 목표 건너뛰기 거절의 실제 주장·인용을 검사하고, 재분석에 구체적인 거절 영역·사유를 전달한다.
- 질문 없는 캐릭터 반응을 허용하고 교사식 문답·도움 주체 뒤바뀜의 검수 분류와 실제 인용·거절 판정을 연결한다. 캐릭터의 MISSING_QUESTION은 스키마·서버에서 차단한다.
- 승인한 S0 단서 기준을 생성·검수에 연결한다. 분석-응답 불일치 거절 때만 짧은 사유·실제 대사 근거를 받고, 정상 근거는 null로 둔다. 캐릭터 모델의 required는 제거하고 서버에서 필수 수정 조건을 복원한다.

잘못된 검수는 기존 한도 안에서 같은 후보를 다시 검수한다. PASS로 강제 변환하지 않는다. 정상 호출 순서·공유 60초·SDK 재시도 0·독립 검수·안전 우선 경로를 유지한다. 외부 HTTP·DB 형태는 유지하며 프론트엔드 후속 변경은 없다.

## 리뷰에서 봐주셨으면 하는 곳

- CharacterModelOutput의 요청별 바인딩·복원과 기존 파서/지원 검사 연결.
- GoalProgressViolation·CharacterInteractionReview·TargetCueViolation의 출처·사유·판정 검사, AnalysisRetry로 이어지는 재분석 근거.
- EvaluationOutputSchema의 캐릭터 모델용 세 배열 수정 조건과 검증 이후 required 복원. 안내자용 기존 네 배열 계약은 유지한다.
- S0 단서의 의미 판단은 모델에 남으며, 스키마 통과만으로 교육적 정확성을 보장하지 않는다는 검증 경계.

## 고민했던 점 · 다른 선택지

서버 지원 보정과 독립 검수를 유지하기 위해 분석·생성을 합치지 않았다. 입력 중복과 서버 소유 출력 항목을 줄이고, 검수 거절에 필요한 근거만 받는다. 재시도 예산·timeout을 늘리는 방법은 사용하지 않았다.

기본 서버·roleplayEval은 compact 경로를 사용한다. legacy 옵션은 과거 형태 진단용이며 옛 배포 바이너리 재실행과 다르다. --prepare-only로 모델 호출 없이 고정 후보의 요청·스키마를 확인할 수 있다. 모델은 기존 .env.local/서버 설정으로 선택하며 키·주소·원문 실험 파일은 커밋하지 않는다.

## 검증과 한계

- 최종 전체 빌드: 2,921개 중 2,915개 통과, 실패·오류 0, 조건부 6개 제외. P1 계약 회귀 13개와 고정 후보 진단 7개 포함.
- 실제 Elice(gpt-6-luna, 추론 low): 현재 계약 P1 한 턴은 17.324초·3회 호출·첫 PASS, 형식/제공자 실패 0, 기대값 3/3. 분석 4.610초·생성 2.912초·검수 9.612초다.
- 실제 고정 후보 검수: 행동 단서는 PASS, 단순 맞장구·교사식 문답·금지 추론은 의도한 사유로 거절해 기대값 4/4. 후보당 1회, 총 검수 4회, 재시도와 분석·생성 호출 없음. 모델 원문에서 required가 빠지고 서버가 복원한 내부 결과도 확인했다.
- 마지막 S0 보완의 문자 수 비용: 같은 P1 검수 요청은 직전 compact 계약보다 약 5.0%, 정상 출력의 동일 JSON 비교는 28자 증가했다. 기존 입력/출력 축소 수치는 별도 보고서의 당시 버전 비교이며 최종 버전의 토큰·속도 절감률로 사용하지 않는다.
- 마이그레이션·공개 금지 파일·공백 검사 통과. 로컬 환경 파일·실험 원문 폴더는 Git 추적 대상이 아니다.

각 실측은 제한된 단건이다. 직전 전체 턴 17.714초와 현재 17.324초는 비슷했고 검수 자체는 9.307→9.612초로 늘었다. 안정적인 속도 개선·10초 달성·모든 입력의 정확성을 주장하지 않는다. 로컬 실행기는 입력 검사·STT·TTS·HTTP·DB 저장을 포함하지 않는다.

실제 Dev의 도와줄까 실패 맥락, 정상 후보의 반복 일관성, primary_gap이 현재 목표와 다음 초점 중 무엇을 나타내는지의 의미 정합성 검토는 남아 있다. GitHub CI·AWS Dev 관측은 아직 수행하지 않았다.
