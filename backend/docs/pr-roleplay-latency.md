# 캐릭터 역할극의 반복 분석과 모델 입출력 비용 축소

## 이번에 한 일

Dev에서 첫 검수까지 약 32초가 걸리고, 목표 초점 변경·도움 제안을 잘못 거절한 뒤 재분석을 반복해 60초 예산을 소모했다. 구체적인 검수 사유도 재분석까지 충분히 전달되지 않았다.

캐릭터 분석·검수의 공통 정책을 적용하고, 목표 건너뛰기 거절의 실제 주장·출처를 검사한다. 재분석에는 거절 영역·사유·수정 대상을 전달한다.

분석·생성에도 native JSON Schema와 작은 모델 전용 출력을 적용한다. 서버 소유 식별자·관찰 참조·후보 메타데이터는 서버가 바인딩·복원하며 기존 의미·지원·안전 검증을 수행한다. 캐릭터 지침과 중복 입력 설명도 축소한다.

실제 P1 비교에서 질문 없는 캐릭터 반응을 거절하며 재생성이 늘어난 문제가 확인됐다. 캐릭터 native 실패 코드에서 MISSING_QUESTION을 제외하고 서버에서도 검사한다. 검수의 발화 방식·실제 인용·거절 판정 일치를 확인하고 재생성 지시가 캐릭터 계약 안에서 적용되도록 보완한다. 잘못된 검수는 같은 후보를 다시 검수하며 PASS로 강제하지 않는다.

## 연결 Task

- 별도 Issue 번호는 지정되지 않았다.
- 로컬 완료 기준: 공통 정책·세부 사유 전달·간결 wire·원본 검증 보존·입출력 크기 비교.
- 실제 모델 단건 비교 후 검수의 역할·질문 정책을 보완했다. 보완 이후 실제 P1 한 턴에서 신규 계약 수용과 첫 PASS를 확인했다. 잘못된 후보 거절·여러 입력·Dev 검증은 남아 있다.

## 리뷰에서 봐주셨으면 하는 곳

- CharacterModelOutput의 요청별 키 바인딩과 복원 후 기존 검증 유지.
- GoalProgressViolation의 실제 주장 검사와 AnalysisRetry로 이어지는 사유 보존.
- 캐릭터 전용 지침에서 지원 이력·독립 달성·종료·안전 정책이 보존됐는지.

## 고민했던 점 · 다른 선택지

분석·생성 통합 대신 현재 서버 지원 보정과 독립 검수를 유지했다. 먼저 중복 지침·입출력을 줄이고, 과거 진단 재생용 기존 형태와 비교할 수 있도록 했다. 실제 속도 개선 여부는 같은 모델·사례로 확인한다.

## 검증과 한계

- 최종 전체 빌드 통과: 2,910개 중 2,904개 통과, 실패·오류 0, 실행 조건이 필요한 6개 건너뜀.
- 새 실제 P1 자료 기반 계약 회귀 검사 9개 통과. 잘못된 검수의 동일 후보 재검수, 유효한 재생성, 반복 실패 한도, 안내자·안전 우선 경로를 확인했다.
- 동일 합성 입력에서 스키마 포함 요청 문자 수: 분석 42.8%, 생성 48.3%, 검수 37.2% 감소. 분석 출력 1,306→542자, 생성 출력 330→42자.
- compact/legacy 합성 제공자 평가 실행기 연결 확인. 두 실행 모두 3회 호출·형식 실패 0이며 가짜 제공자의 기대값은 1/3으로 동일하다.
- 마이그레이션·공개 금지 파일·diff 검사 통과. 실제 키·로컬 환경 파일·실험 결과 폴더는 커밋하지 않는다.

실제 Elice P1 비교는 기존 형태 27.335초·3회 호출·첫 PASS, 축소 형태 46.720초·7회 호출·재생성 두 번 후 PASS였다. 축소 형태 최초 세 호출은 19.428초, 입력 토큰은 27,339→14,506으로 줄었지만 추가 호출 27.055초로 턴 전체는 늘었다. 질문 없는 캐릭터 반응의 거절과 감정을 묻는 재생성 유도에서 정책 정합성 문제가 남았다. 이후 캐릭터 질문·상호작용 계약을 서버에서 보완하고 위 로컬 검사를 통과했다. 보완 이후 별도 승인받은 실제 P1 한 턴은 17.714초·3회 호출·첫 PASS였고 질문 없는 캐릭터 반응이 승인됐다. 형식·제공자 실패 0, 기대값 3/3이며 검수는 9.307초였다. 각 단건이므로 안정적인 속도 개선이나 배포 준비 완료로 보지 않는다. 합성 제공자 smoke는 새 wire과 실행기 연결 검사다.

정상 호출 수·공유 60초·독립 검수·안전 우선 경로를 유지한다. 외부 HTTP·DB 구조·프론트엔드 변경은 없다. 기존 진단 재생 경로는 유지하며 서버와 평가 실행기는 기본 compact 경로를 사용한다.
