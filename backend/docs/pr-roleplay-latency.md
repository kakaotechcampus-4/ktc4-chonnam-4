# 캐릭터 역할극의 반복 분석과 모델 입출력 비용 축소

## 이번에 한 일

Dev에서 첫 검수까지 약 32초가 걸리고, 목표 초점 변경·도움 제안을 잘못 거절한 뒤 재분석을 반복해 60초 예산을 소모했다. 구체적인 검수 사유도 재분석까지 충분히 전달되지 않았다.

캐릭터 분석·검수의 공통 정책을 적용하고, 목표 건너뛰기 거절의 실제 주장·출처를 검사한다. 재분석에는 거절 영역·사유·수정 대상을 전달한다.

분석·생성에도 native JSON Schema와 작은 모델 전용 출력을 적용한다. 서버 소유 식별자·관찰 참조·후보 메타데이터는 서버가 바인딩·복원하며 기존 의미·지원·안전 검증을 수행한다. 캐릭터 지침과 중복 입력 설명도 축소한다.

## 연결 Task

- 별도 Issue 번호는 지정되지 않았다.
- 로컬 완료 기준: 공통 정책·세부 사유 전달·간결 wire·원본 검증 보존·입출력 크기 비교.
- 실제 모델 단건 비교를 수행했으며, 검수의 역할·질문 정책 정합성은 후속 보완이 필요하다.

## 리뷰에서 봐주셨으면 하는 곳

- CharacterModelOutput의 요청별 키 바인딩과 복원 후 기존 검증 유지.
- GoalProgressViolation의 실제 주장 검사와 AnalysisRetry로 이어지는 사유 보존.
- 캐릭터 전용 지침에서 지원 이력·독립 달성·종료·안전 정책이 보존됐는지.

## 고민했던 점 · 다른 선택지

분석·생성 통합 대신 현재 서버 지원 보정과 독립 검수를 유지했다. 먼저 중복 지침·입출력을 줄이고, 과거 진단 재생용 기존 형태와 비교할 수 있도록 했다. 실제 속도 개선 여부는 같은 모델·사례로 확인한다.

## 검증과 한계

- 전체 빌드 통과: 2,901개 중 2,895개 통과, 실패·오류 0, 실행 조건이 필요한 6개 건너뜀.
- 이후 지침 문구 명확화에 대해 관련 25개 검사와 최종 리소스 패키징/정적 검사(`build -x test`) 통과. 전체 Java 회귀 결과를 재사용했다.
- 동일 합성 입력에서 스키마 포함 요청 문자 수: 분석 42.8%, 생성 48.3%, 검수 37.2% 감소. 분석 출력 1,306→542자, 생성 출력 330→42자.
- compact/legacy 합성 제공자 평가 실행기 연결 확인. 두 실행 모두 3회 호출·형식 실패 0이며 가짜 제공자의 기대값은 1/3으로 동일하다.
- 마이그레이션·공개 금지 파일·diff 검사 통과. Gitleaks v8.30.1로 이번 작업 2개 커밋에서 비밀값 검출 없음을 확인했다.

실제 Elice P1 비교는 기존 형태 27.335초·3회 호출·첫 PASS, 축소 형태 46.720초·7회 호출·재생성 두 번 후 PASS였다. 축소 형태 최초 세 호출은 19.428초, 입력 토큰은 27,339→14,506으로 줄었지만 추가 호출 27.055초로 턴 전체는 늘었다. 질문 없는 캐릭터 반응의 거절과 감정을 묻는 재생성 유도에서 정책 정합성 문제가 남았다. 이 상태를 속도 개선 완료나 배포 준비 완료로 보지 않는다. 두 단건만으로 안정성·성능 분포는 판단하지 않는다. 합성 제공자 smoke는 새 wire과 실행기 연결 검사다.

정상 호출 수·공유 60초·독립 검수·안전 우선 경로를 유지한다. 외부 HTTP·DB 구조·프론트엔드 변경은 없다. 기존 진단 재생 경로는 유지하며 서버와 평가 실행기는 기본 compact 경로를 사용한다.
