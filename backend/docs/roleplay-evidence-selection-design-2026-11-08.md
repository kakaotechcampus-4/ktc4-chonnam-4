# 원문·참조 복사를 근거 키 선택으로 바꾸는 진단 설계

작성일: 2026-11-08\
상태: 승인 범위의 테스트용 구현·관련 검사·실제 A/B 두 호출 완료. 의미 판단 실패로 운영 적용하지 않음.

## 목표와 해결하지 못하는 부분

직전 통합 평가에서 A는 SUPPORTED/MATCHED_EXPRESSION인데 인용이 null이었고,
B는 기준 참조를 오기하고 후보 대사를 아동 발화의 근거로 인용했다.
이 중 원문·참조를 다시 작성하다 생기는 오류는 모델이 작성할 데이터를 줄여 구조적으로 제한할 수 있다.

모델은 의미 판단과 근거 선택을 수행하고, 이미 서버에 있는 문장·UUID·기준 해시는 서버가 연결한다.
현재/활동 목표·후보 checks·최종 decision의 의미 판단은 유지한다.
B의 PRIMARY_GAP_MISMATCH 설명처럼 후보 품질을 분석 오류로 판단하는 문제는 별개로 남아 있다.
이번 변경을 그 의미 혼동까지 해결하는 방법으로 주장하지 않는다.

우선 테스트용 통합 진단으로 검증한다. 현재 운영 v4·평가 v7 구현과 검증기는 유지한다.
통과하지 않는 모델 응답의 누락 필드를 기존 계약에 임의 보충하는 변경은 하지 않는다.

## 관찰 근거: 인용 추출에서 원문 참조로 계약 변경

모델 출력에서 evidence_quote를 제거하고 evidence_source를 받는다.

- u0: 이번 learner_turn.canonical_utterance 전체에 대한 참조.
- NONE: 인용할 표현을 주장하지 않음.

모델 요청에는 u0가 이번 아동 발화라는 연결을 명시한다. 후보·이전 대화는 u0가 아니다.
원문은 이미 learner_turn에 있으므로 별도 카탈로그에 다시 복사하지 않는다.
서버는 명시적으로 선택된 u0만 이번 원문에 연결하고, NONE은 null에 연결한다.
키 누락·알 수 없는 키는 실패이며 설명의 문장으로 추측하거나 u0로 고치지 않는다.

이것은 ‘모델이 구체 구절을 추출했다’는 계약에서 ‘모델이 이번 원문 전체를 근거로 선택했다’는 계약으로의 변경이다.
복원된 원문을 모델이 직접 인용한 것처럼 기록하지 않는다.
특정 구절을 선택하는 정밀도는 제공하지 않으며, 원문 전체가 해당 학습 증거를 뒷받침하는지는 계속 의미 판단이 필요하다.
현재도 검증기는 인용의 출처·비어 있지 않음·상태/사유를 검사하며 교육적 타당성 자체를 판정하지 않는다.

### 상태·판정·사유·출처를 함께 제약

각 관찰 키의 스키마에 다음 조합만 허용한다. verdict를 SUPPORTED로 고정하지 않는다.

| 원본 관찰 status | verdict | reason_code | evidence_source |
| --- | --- | --- | --- |
| NOT_EXPRESSED 외 | SUPPORTED | MATCHED_EXPRESSION | u0 |
| NOT_EXPRESSED | SUPPORTED | ABSENCE_CONFIRMED | NONE |
| NOT_EXPRESSED 외 | UNSUPPORTED | NO_MATCHING_EXPRESSION | NONE |
| 모든 status | UNSUPPORTED | STATUS_MISMATCH | u0 |
| 모든 status | INSUFFICIENT_CONTEXT | INSUFFICIENT_CONTEXT | NONE |

모든 분기에 explanation은 빈 값이 아닌 한글 200자 이하로 요구한다.
각 행 조합은 닫힌 객체 스키마로 구성하고 관찰 키 내부의 anyOf로 묶는다. 최상위는 object를 유지한다.
이렇게 하면 EXPLICIT 승인에 NONE을 고르는 조합은 원천적으로 허용되지 않는다.
의미가 틀린 SUPPORTED/u0 선택까지 스키마가 막는 것은 아니다. B의 잘못된 감정 관찰 거절을 별도로 확인한다.

## 활동 근거: 긴 참조 대신 서버 키 선택

이번 분석 관찰과 이전 확정 관찰의 실제 reference 집합을 서버가 r0, r1 등의 키로 연결한다.
승인 기준에만 있고 관찰에는 없는 참조는 카탈로그에 넣지 않는다. 기존/현재 관찰과 당시 맥락은 구분한다.
카탈로그에는 각 키의 실제 reference·status·현재/확정 출처를 제공하고, 원본 매핑을 로컬 산출물에도 보존한다.

activity_review의 evidence_references를 evidence_selection 객체로 바꾼다.

```json
{
  "evidence_selection": {
    "r0": true,
    "r1": false
  }
}
```

형식 예시이며 실제 요청에 이 선택값을 정답으로 보내지 않는다.
스키마는 실제 키만 필수 Boolean 속성으로 허용하고 추가 키를 금지한다. 모델이 UUID/해시를 다시 쓰지 않는다.
서버는 true인 키만 원본 reference로 복원한다. 없는 키를 유추하거나 가장 비슷한 해시로 수정하지 않는다.
선택 가능한 참조가 없으면 빈 객체다. true 선택이 없으면 기존처럼 빈 참조 목록이다.
참조 선택의 타당성, ACHIEVED의 긍정 basis 조건 등은 기존 활동 검증기를 그대로 적용한다.

키별 Boolean을 모두 출력하므로 관찰 이력이 많을 때 출력량이 늘 수 있다.
이번 P1 카탈로그는 A 1개·B 2개이며 일반 운영 데이터의 비용/스키마 크기는 아직 검증하지 않았다.
성공했다고 관찰 이력을 임의로 잘라내거나 자동으로 운영 적용하지 않는다.

## 테스트용 변환과 기존 검증

새 진단은 기존 운영 v4의 범위별 입력·후보·checks·decision·기타 검수 필드를 유지한다.
원문 참조 키와 실제 참조 키의 카탈로그를 추가하고 근거 출력 표현만 변경한다.
프롬프트는 새 계약에 맞춰 구절 복사·긴 참조 작성을 요구하던 지시를 갱신한다.
버전은 roleplay-evidence-selection-diagnostic/v1, 스키마 evidence-selection-diagnostic/v1이다.

응답 처리 순서:

1. 새 네이티브 스키마와 같은 스키마로 수신 검증한다.
2. 명시적으로 선택된 출처/참조만 원본 값에 연결한다.
3. 복원한 기존 v4 형태를 기존 운영 파서와 검증기에 전달한다.
4. 의미 판단·분기·코드·PASS 조건·판단보류를 그대로 검사한다.

모델 raw 응답과 서버가 원본을 연결한 결과는 구분해서 보존한다.
새 source 키를 선택하지 않은 응답이나 과거 v4 실패 원문에 자동 인용/참조를 채워 넣지 않는다.
verdict·reason_code·decision·checks를 바꿔 통과시키지 않는다.
안전/입력 확인의 null 학습 검수, 공유 예산과 기존 최종 전달 게이트도 유지한다.

## 승인 후 실행 범위

테스트용 빌더·동적 스키마·매핑 어댑터·별도 실행 작업만 추가한다.
오프라인에서는 조합 오류·없는 키·누락·다른 요청의 매핑·참조 복원·판단보류·안전 우선순위를 확인한다.
원문/참조 연결 후 기존 검증을 통과했는지 검사하고, 의미 판단의 정답과 구분한다.
관련 검사와 형식 검사만 수행하며 운영 코드가 바뀌지 않으면 전체 check는 반복하지 않는다.

실제 실행은 동일 고정 A/B와 같은 후보, Elice gpt-5.4-nano로 최대 두 번이다.
공유 60초, SDK/진단 재시도 0회, 기존 timeout·출력 토큰 상한을 유지한다.
별도 호환성 호출은 추가하지 않는다. 새 anyOf 조합을 제공자가 거절하면 실패로 기록하고 중단한다.
제공자·시간·스키마 실패는 중단하고, 의미/근거 오류나 거절은 기록 후 예정된 다른 사례를 한 번만 수행한다.

사전 기대값은 직전 운영 연결 설계와 같다.

- A: 사건·현재 목표·활동·해석/전략은 승인. 후보 판정은 별도로 평가하며 PASS를 강제하지 않는다.
- B: 사건 승인·감정 거절. 현재 사건 목표·활동 IN_PROGRESS·해석/전략을 관찰 오류와 구분하며 전체 분석은 거절한다.
- 기계적 복사 오류 제거뿐 아니라 B의 의미 혼동이 남았는지도 확인한다.

결과 폴더는 build/eval/elice-p1-evidence-selection-01이다. 이미 있으면 호출 전에 중단한다.
요청·스키마·카탈로그·모델 raw 응답·원본 연결 결과·기존 검증 결과·시간/토큰·버전/해시를 보존한다.
결과를 보고 원문 참조 방식의 타당성과 운영 적용/검수 분리 여부를 별도 판단한다.
운영 코드·공개 API·DB·프론트엔드·완료 정책·모델 교체·추가 호출·commit/push는 이번 범위에 포함하지 않는다.

## 공식 문서와 적용 한계

- [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat): 제한된 스키마 집합을 지원하고 최상위 anyOf는 허용하지 않는다. 이번 조합은 객체 속성 내부에 둔다.
- [Spring AI 네이티브 출력](https://docs.spring.io/spring-ai/reference/api/structured-output/native.html): 제공자/모델마다 스키마 지원 범위가 다르므로 실제 호환성을 확인해야 한다.

기존 Spring AI 버전·호출 방식을 바꾸는 작업은 아니다. 공식 OpenAI 지원이 Elice 프록시의 동일 지원을 보장하지 않는다.

## 실행 결과와 적용 판단

관련 테스트 39개가 실패·오류·제외 없이 통과했고 spotlessCheck도 통과했다.
이번 단계는 테스트용 코드·프롬프트·실행 작업만 추가했으며 운영 코드와 v4 계약은 변경하지 않았다.
전체 검사는 직전 운영 통합 단계의 성공 결과를 유지하고 이번 테스트 전용 변경에는 반복하지 않았다.

Elice gpt-5.4-nano로 예정한 두 호출만 수행했다. 응답 모델은 gpt-5.4-nano-2026-03-17이다.
재시도·추가 호출은 없고 두 응답 모두 새 스키마와 원본 연결 후 기존 서버 검증을 통과했다.
이는 출력 구조와 판정 정합성이 유효하다는 뜻이며, 분석 검수의 의미가 맞았다는 뜻은 아니다.

| 사례 | 시간 | 입력/출력 토큰 | 의미 판단 결과 |
| --- | --- | --- | --- |
| A: 정상 사건 분석 | 4.207초 | 8,371 / 479 | 사건 관찰은 승인했으나 후보 대사의 부족을 이유로 현재 목표와 활동 계속 판정을 거절함 |
| B: 잘못된 감정 관찰 추가 | 10.793초 | 8,886 / 519 | 후보의 ‘멍해졌어’를 아동 감정 표현처럼 판단해 잘못된 감정 관찰까지 승인함 |

합계는 15.000초, 입력 17,257토큰·출력 998토큰이다. 제공자 호출 시간 합계는 14.963초다.
단가가 설정되지 않아 금액은 계산하지 않았다. 관찰 verdict 기대값은 A 1/1, B 1/2로 전체 2/3이다.
두 사례 모두 최종 REANALYZE이며 safe_to_send=false다. 실제 사용자 전달·DB 저장을 실행한 실험은 아니다.
B의 최종 거절은 현재 목표 검수 거절에서 발생했으므로, 잘못된 감정 관찰을 올바르게 검출한 성공으로 세지 않는다.

핵심 실패는 출처 혼동이다. 아동 원문은 ‘너 발표하다가 말을 못 찾아서 중간에 멈추고 그냥 앉았지?’이며,
‘멍해졌어’는 후보 대사에만 있다. 모델은 후보 내용을 근거로 감정 관찰을 승인하면서 u0를 선택했다.
서버가 u0를 아동 원문 전체에 연결하므로, 기존 인용 출처 검사는 통과하지만 모델 설명의 출처 혼동은 잡지 못한다.
이는 구체 인용에서 원문 전체 참조로 바꾸면서 잃는 검출 능력이 실제로 드러난 것이다.

따라서 이 원문 전체 선택 방식은 관찰 근거의 운영 계약으로 채택하지 않는다.
참조 키의 기계적 오류 제거와 검수 품질 개선은 별도로 판단해야 한다.
두 건으로 모델 전반의 성능이나 원인별 영향을 일반화하지 않으며, 원래 서비스 문제도 해결 완료로 처리하지 않는다.
후속 후보는 분석 검수와 후보 검수의 입력을 물리적으로 나누는 설계지만, 추가 호출·지연·비용을 포함해 별도 검토해야 한다.
이번 승인 범위에서 그 변경을 구현하거나 추가 유료 호출·commit/push를 수행하지 않았다.

원본 요청·응답·스키마·카탈로그·연결 결과·메타데이터와 요약은 build/eval/elice-p1-evidence-selection-01에 보존했다.
