# 운영 역할극 입력 검사기

## 기준과 범위

기준 develop: e09bbbf. PRI-04/06, INP-07~13, SAFE-02~05 및 DEC-016/027/039를 적용한다.
음성은 기존 STT 품질 검사 뒤, 텍스트는 직접 같은 운영 검사기를 사용한다.
기존 API·실패 원장·체크포인트·DB 마이그레이션·프론트엔드는 변경하지 않는다.

## 실행 흐름

1. 인증된 실행 컨텍스트의 childId로 등록 실명을 읽는다. 실명 조회 장애/아동 부재는 검사 불가다.
2. 서버에서 공백을 최소 정제한다. 부정·이유·감정·대상은 바꾸지 않는다. 제어/보이지 않는 문자·잘못된 서로게이트는 재입력으로 처리한다.
3. 등록 실명, 명시적인 자기 이름, 숫자형 휴대전화·이메일·주민번호 형태를 가린다. 공백 정리만으로 마스킹 여부를 true로 만들지 않는다. 학교·주소·구어체 번호 등 범위가 불명확한 개인정보 단서는 외부 호출 없이 재입력으로 돌린다.
4. 기존 LlmProvider/StructuredLlmExecutor로 INPUT_VALIDATION을 한 번 호출한다. 모델은 가려진 문자열의 의미·안전만 판정하며 표준 발화를 재작성하거나 원문을 반환하지 않는다.
5. 결과 스키마를 엄격히 확인한다. ANALYZABLE은 의미 보존·개인정보 미잔류 확인과 유효한 신뢰도가 모두 있어야 통과한다. confidence는 모델의 자기 보고 값이며 보정된 품질 점수가 아니다. 별도 통과 임계값을 임의로 추가하지 않았다.
6. Accepted는 서버가 만든 하나의 표준 발화와 판정값만 기존 분석/생성/검수에 넘긴다. REINPUT/UNSAFE/UNAVAILABLE은 기존 재입력/안전 중단/턴 재시도 경로를 사용한다.

모델 판정 요청에는 원문·실명·추적 ID를 userPrompt에 함께 보내지 않는다. 로컬 추적 컨텍스트와 호출 예산은 기존 제공자 계약대로 관리한다.
검사에도 동일한 RoleplayTurnDeadline/AiCallBudget이 적용된다. 내부 자동 재시도를 추가하지 않았으며 호출/형식 장애는 Unavailable이다. 전체 기한 초과/취소/늦은 결과는 기존 시간 초과 처리가 우선한다.

## 빈 등록과 제공자

roleplay.http.enabled=true일 때 ModelRoleplayInputProcessor가 등록된다. 기존 LlmProvider, JsonMapper, 실명 조회 서비스가 필요하다. 별도의 모델/키/HTTP 활성화 기본값을 추가하거나 배포 환경을 켜지 않는다. 명시적인 대체 빈은 허용하지만 운영에 테스트 대체 구현을 연결하면 이 검증의 의미가 없어진다.

process(String)은 실행 컨텍스트 없이 운영 처리를 시작하지 않고 Unavailable을 반환한다. 파이프라인은 process(Input)을 사용한다. 기존 테스트용 람다 호환을 위한 기본 메서드는 유지한다. 새 운영 호출자는 인증된 trace와 현재 deadline을 함께 전달해야 한다.

## 보관과 실패

검사기는 원문·정제문·위험 판정 상세를 저장하거나 로그로 출력하지 않는다. 입력·마스킹 중간값의 toString은 본문을 숨긴다. 정상 결과의 기존 품질/표준 발화 보관은 완료 즉시/미완료 마지막 활동 24시간 삭제 경로를 그대로 따른다.
위험/검사 장애는 학습 턴을 확정하거나 목표·지원·보상·음성 실패 원장을 갱신하지 않는다. 일반 음성 입력의 의미 불명확은 기존 입력 실패 집계 정책을 따른다. 위험 고정 문구·강사 전달은 기존 안전 결과/안내 공급 경로에 의존하며 새 알림 기능이나 사건 저장을 만들지 않는다.

## 품질과 운영 한계

로컬 개인정보 탐지는 명시된 패턴과 등록 실명에 한정된다. 모든 사람 이름·주소·학교·구어체 식별정보를 완전하게 식별하는 NER 구현은 아니다. 일부 개인정보 단서는 보수적으로 재입력시켜 정상 문장이 거절될 수 있다. 탐지되지 않은 정보가 판정 제공자에 도달할 가능성까지 없앴다고 주장하지 않는다. 모델의 privacyClear 판정은 전송 전 탐지를 대체하지 않는다.

실제 모델의 위험/욕설/이야기 속 사건 구분, 개인정보 탐지 누락과 과잉 거절은 합성 품질 세트로 실측해야 한다. 제공자의 입력 보관·학습 이용 조건(DEC-040), 개인정보 탐지 범위 및 고정 안전 안내 승인, 기존 음성 전달 구현·브라우저 연동도 운영 인수에 필요하다. 프롬프트 지시와 대역 테스트 통과만으로 해당 품질이 보장되지는 않는다.

프롬프트는 prompts/roleplay/v1/input-validation.md, 출력은 input-judgment/v1, 최소 정제 정책 표시는 input-minimal-v1이다. 이 버전 표시는 새로운 제품 정책 승인이 아니다.

## 프론트엔드 전달사항

API 필드/경로는 유지한다. 신규 성공 acceptedInput은 서버에서 가린 표준 발화이며 원본 STT가 아니다. 재전송·실패에는 acceptedInput이 없다. 기존 REINPUT_REQUIRED/RETRY_REQUIRED/STOPPED와 action을 구분하고 검사 장애를 아동 오답으로 표시하지 않는다. 개인정보가 포함된 원문을 브라우저 영구 저장소나 로그에 남기지 않고 기존 완료 시 사본 삭제 정책을 적용해야 한다.
