# Gemini 4 Argon 후보 검수 비교 설계

작성일: 2026-11-08\
상태: 설계 완료·승인 대기. 코드·환경 설정 변경·추가 API 호출 없음.

## 확정 조건과 비교 목적

사용자가 지정한 요청 모델은 google/gemini-4-argon이며 기존 Elice 접속 주소와 키를 유지한다.
이름을 추측하거나 다른 모델 ID로 대체하지 않는다. 키·접속 주소를 산출물에 복사하지 않는다.

이번에는 후보 평가 모델만 교체한다. 분석·생성·서버 규칙·프롬프트를 함께 바꾸지 않는다.
앞서 제안한 서버 형식 검사 분리 설계는 이번 비교에 포함하지 않는다.
전체 서비스의 기본 모델 변경과 분석/생성까지의 재실행은 비교 결과 확인 후 별도 범위로 정한다.

목적은 기존 Nano에서 관찰한 역할 구별 실패와 잘못된 물음표 판단이 새 모델에서도 나타나는지 확인하는 것이다.
모델 교체가 모든 구조·의미 문제를 해결한다고 전제하지 않는다.

## 고정 사례와 기준 결과

기준 실행은 build/eval/elice-p1-candidate-role-01이다.

| 사례 | 고정 후보 | 역할 기대값 | Nano에서 관찰한 결과 |
| --- | --- | --- | --- |
| A | (고개를 살짝 숙이며) 응… 발표하다가 멈췄어. 그때 좀 멍해졌어. | IN_CHARACTER | IN_CHARACTER, PASS, 3.574초 |
| C | 친구가 발표하다가 말을 찾지 못해서 자리에 앉았어. | SELF_AS_THIRD_PERSON_NARRATION | IN_CHARACTER, REGENERATE, 3.726초. 물음표 0개인데 MULTIPLE_QUESTIONS 출력 |

두 사례 모두 기존 승인 분석·다음 감정 목표·S0 지원을 유지한다.
A의 역할 기대값과 후보 전체의 적절성은 다르다. S0에서 상태 표현이 적절한지 별도 검토하고 PASS를 정답으로 강제하지 않는다.
C는 최종 거절 여부가 아니라 자기 캐릭터의 제3자 서술을 역할 이탈로 식별했는지 확인한다.
MULTIPLE_QUESTIONS와 실제 물음표 수의 일치 여부는 서버 검증 통과와 별도로 기록한다.

## 입력·프롬프트·스키마 고정

Nano 기준 실행의 A/C request.json, system-prompt.md, schema.json과 원본 결과를 테스트 자원으로 고정한다.
당시 source.json의 해시와 실제 파일을 대조한 뒤 보존한다. 기존 승인 분석 기록도 현재 검증기로 다시 확인한다.
원본 누락·불일치 시 중단하며 별도 분석/생성 호출로 대체하지 않는다.

제공자에 보내는 사용자 메시지·시스템 프롬프트·네이티브 스키마는 기준 실행의 문자열을 그대로 사용한다.
현재 진단 입력 및 검증기와 일치하는지 사전에 확인한다.
JVM별 enum/required 순서 차이는 제약 비교에서만 정규화하고, 전송 문자열과 해시는 기준 실행 그대로 유지한다.
추적용 새 요청 ID는 부여하되 모델 입력에 정답·사례 이름·이전 Nano의 답·오류를 추가하지 않는다.

새 모델도 기존 OpenAI 호환 연결의 네이티브 구조화 출력과 strict=true를 사용한다.
제공자가 이를 거절하면 호환성 실패로 기록한다. 프롬프트만으로 JSON을 요구하는 방식으로 자동 전환하지 않는다.

## 테스트용 구현 범위

기존 CandidateRoleDiagnostic의 고정 사례·검증·호출 상한을 재사용하는 별도 비교 실행기를 추가한다.
Nano 전용 실행 작업·출력 폴더·과거 원문을 수정하거나 덮어쓰지 않는다.
기존 .env.local의 AI_MODEL도 이번 실험을 위해 영구 변경하지 않는다.
실행 시 google/gemini-4-argon을 명시하고 기존 Elice 주소·키·timeout·출력 토큰 상한·추론 설정을 사용한다.
환경 설정 값의 변경이 필요한 제공자 오류가 나오면 기록하고 중단하며 임의로 설정을 바꿔 재시도하지 않는다.

기존 후보 파서·역할 인용·코드/check 정합성·독립 분석 승인·최종 전달 조건을 유지한다.
새 모델 응답을 보정하거나 틀린 코드를 삭제하지 않는다.
역할 라벨·역할 설명·서버 수용·실제 내용과의 일치·최종 판정을 분리해 기록한다.

응답 메타데이터의 모델명도 기록한다. google/gemini-4-argon 또는 gemini-4-argon 이외의 값이거나
모델명이 없으면 대상 모델 확인 실패로 중단한다. 특히 Nano 응답을 Argon 결과로 집계하지 않는다.
다른 버전 이름이 반환되면 원문을 보존하고 별도 확인하며, 임의의 문자열 유사도로 통과시키지 않는다.
이는 응답 메타데이터의 일치 확인이며 프록시 내부 모델 실행을 독립적으로 증명하는 것은 아니다.

## 검증과 외부 호출 상한

먼저 외부 호출 없이 다음을 검증한다.

- 기존 A/C 메시지·프롬프트·스키마·버전·해시 유지, 기대값과 Nano 응답의 모델 입력 유입 없음.
- 기존 승인 분석 재검증과 파일 불일치 시 호출 전 중단.
- 대상 모델만 선택되고 응답 모델명 불일치/누락 시 중단.
- 기존 의미/근거/코드 모순 거절·안전 우선순위·최종 전달 조건 유지.
- 최대 두 호출·재시도 없음·공유 예산·취소·늦은 응답 폐기·별도 산출물 보존.

관련 검사와 형식 검사만 실행한다. 운영 코드를 바꾸지 않으므로 전체 check는 반복하지 않는다.

실제 호출은 A 1회 → C 1회, 최대 2회다. 분석·생성·연결 확인·Nano 재측정 호출은 없다.
SDK/진단 재시도 0회, 두 호출의 공유 예산 60초다.
제공자·시간·스키마·실행·응답 모델 확인 실패는 즉시 중단한다.
역할/근거/코드 정합성 오류는 기록 후 예정된 다른 후보 한 건만 실행한다.
실패했다고 프롬프트·제약·설정을 바꾸어 추가 호출하지 않는다.

결과 폴더는 build/eval/elice-argon4-p1-candidate-role-01이다. 이미 있으면 호출 전에 중단한다.
요청 모델·응답 모델·각 원문·고정 해시·검증·역할 기대값·물음표 수·판정·시간·토큰·중단 이유를 보존한다.
비밀이 아닌 실제 timeout·출력 토큰 상한·추론 설정도 확인 가능한 범위에서 기록한다.
기준 실행 당시 설정 기록이 부족한 항목은 동일성이 입증된 것으로 쓰지 않는다.

## 해석과 승인 범위

두 사례에서 더 나은 결과가 나와도 일반적인 정확도·안정성이나 모델 전반의 우열로 확대하지 않는다.
모델마다 토큰화·단가가 달라 토큰 수만으로 비용 우열을 판단하지 않는다. 단가 미설정이면 금액은 계산하지 않는다.
후보 검수 시간은 전체 턴 시간이 아니며, 기존 Nano와 이번 Argon은 실행 시점이 다른 단건 측정이다.
공급자 호환성 실패와 의미 판단 실패도 구분한다.

승인 요청 범위는 테스트용 비교 실행기·고정 자원·관련 검사·최대 두 유료 호출이다.
운영 코드/기본 모델·DB·공개 API·프론트엔드·지원/완료 정책 변경·추가 호출·commit/push는 포함하지 않는다.
