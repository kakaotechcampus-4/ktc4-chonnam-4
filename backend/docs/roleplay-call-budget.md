# 역할극 외부 호출 예산

PR #49 R4: 외부 호출의 고정 제한 시간이 남은 턴 예산보다 길 수 있는 문제를 보완한다.
CloudFront와 턴 예산의 관계(R3)는 이번 수정에서 보류하며, 기존 기본값과 최대 상한 60초를 유지한다.

## 호출 경로

```text
RoleplayTurnDeadline.callBudget()
  → STT/TTS 요청 또는 RoleplayRetryContext
  → LlmRequest.withCallBudget()
  → 실제 제공자 어댑터
  → min(설정된 제공자 제한 시간, 현재 남은 턴 시간)
```

`AiCallBudget`은 남은 시간 조회를 위임받는 내부 객체다. 요청을 만드는 순간의 시간을 고정하지 않고,
어댑터가 제한 시간을 적용하는 시점에 다시 조회한다. 만료·취소됐으면 `RoleplayTurnDeadline.Expired`가
전파되어 기존 시간 초과 복구 경로로 종료하며, 새 외부 호출로 진행하지 않는다.

STT/TTS는 각 시도에 이 객체를 전달한다. LLM은 재시도 컨텍스트를 통해 분석·생성·평가 각각에 전달한다.
예를 들어 TTS 설정 상한이 15초라도 턴 시간이 3초 남았다면 요청 제한은 3초 이하로 계산된다.

## 실제 제공자 적용

- STT/TTS: 공유 JDK `HttpClient`는 재사용한다. 요청별 `RestClient` 복사본과 요청 팩터리를 사용해
  `JdkClientHttpRequestFactory`의 읽기 제한에 남은 예산을 적용한다. 공유 팩터리의 값을 변경하지 않는다.
  연결 제한의 기본 상한은 공유 클라이언트 설정에 남아 있으며, 요청 실행의 제한은 Spring의 요청 타이머로
  응답 대기와 본문 수신까지 적용된다. 사용 중인 Spring Web 7의 구현은 제한 만료 시 future 취소 또는
  응답 본문 닫기를 시도한다.
- LLM: `OpenAiChatOptions`에 호출별 제한을 전달한다. Spring AI 2의 SDK 재시도는 클라이언트 생성 시 결정되므로,
  역할극 HTTP 활성화 시 제공자 설정과 실제 OpenAI ChatModel 옵션의 재시도가 0회인지 검사한다.
  `callBudget`이 있는 호출에서도 검사하며, 0회가 아니면 외부 호출 전에 실패한다. 호출 옵션에도 0회를 전달한다.
- 예산이 없는 기존 호출은 기존 제공자 제한과 재시도 설정을 유지한다. 기존 요청 생성자는 그대로 사용할 수 있다.

## 유지되는 동작과 한계

- 전체 턴 예산, 단계별 재시도·후보 상한, TTS 실패 시 텍스트 응답, 늦은 결과의 저장 차단은 유지한다.
- 원본 음성·발화·제공자 키·예산 객체를 외부 요청 JSON이나 아동 응답에 새로 노출하지 않는다.
- 로컬 HTTP 제한·취소는 제공자가 원격에서 시작한 AI 작업을 되돌리거나 과금을 취소하는 기능이 아니다.
- JVM 스케줄링·요청 준비·DB·입력 IO·최종 COMMIT·음성 주소 발행까지 엄격한 물리적 종료를 보장하지 않는다.
  취소에 반응하지 않는 작업의 처리권은 여전히 실제 작업 종료 때 해제한다.
- 새 제공자 구현도 요청의 `callBudget`과 호출당 1회 시도 계약을 지켜야 한다. 테스트 대체 구현만으로
  실제 네트워크 제한 동작을 확인했다고 판단하지 않는다.
